# The generated TypeScript codec table

With `[backend.typescript] codec = true`, `ridl-backend-ts` writes
`<base>.codec.ts` beside `<base>.ts` for every package that has a payload root
with a codec, its own or a foreign scalar its interfaces name, or a supported
stream call, and for `ridl.std` when a package's codec file imports it. The file
gives a TypeScript program the facts it needs to send and read the payloads of a
package through the wasm codec of
[ADR-0020](../decisions/ADR-0020-third-encoding-runtime-layering-and-plugin-system.md)
decision 7: one `encode<Name>` and one `decode<Name>` per payload type, over
plain objects; one table per interface that gives each interaction its address,
its kind and its payload functions; typed functions for supported stream
interactions; and the catalog name, the catalog hash, the payload type names and
the rule texts that the wasm module is loaded with. `@driftsys/ridl-runtime`
resolves the wasm type ids from those names.

This is the design as built. The code and its tests are the source of truth;
where this record and the code differ, this record is corrected. The original
decisions keep their numbers D-1 to D-15; the stream decisions below continue
that sequence. The original design is archived as
[`2026-10-22-ts-codec-table-design.md`](../archive/2026-10-22-ts-codec-table-design.md),
with its plan beside it; that note also holds the alternatives considered.
[The generated code chapter](../book/generated-code.md#typescript) is the user's
description.

## What is generated

The codec file is written from the request's model only (`model.interfaces`,
`model.tuples`, `model.flatbuffers`, `model.catalog`), never from the raw IR
(D-1), so it follows the direction
[the codegen plugins record](codegen-plugins.md) sets for the port of this
backend. `<base>.ts` is unchanged by the option. The public `generate(package)`
of the crate does not write the file: only the request's model carries the
catalog hash of the unit that the wasm module is built from.

Its exports:

- `CATALOG_NAME` and `CATALOG_HASH` (32 bytes) — the unit's catalog.
- `PAYLOAD_TYPES` — the qualified names of the package's payload types, sorted.
- `RULES` — the rule texts of the wasm module, `WASM_RULES`; rule code `n` is at
  index `n - 2`.
- `RuleError` — the error class the converters throw for a value they refuse,
  with the `rule` it breaks (an entry of `RULES`). It is written when the module
  reaches an enum or an enum set.
- `encode<Name>(value: Name): Uint8Array` and
  `decode<Name>(bytes: Uint8Array): Name` for every payload type — every
  FlatBuffers root of the package with a finite bound, the set that has a
  `Payload<FlatBuffers>` impl and an entry in `WASM_PAYLOAD_TYPES` (D-2). `Name`
  is the type `<base>.ts` exports. `flatc`'s classes, builders and `<Name>Box`
  tables never appear in a signature.
- `export interface <InducedName.rust>` for every induced tuple that is a
  payload type — the parameter list of a call that is not exactly one named
  type, and a tuple reply of a query (D-9). An induced tuple with no field is
  `export type <InducedName.rust> = Record<string, never>`, the same object
  type, because an empty `interface` is a lint finding.
- `export const <Interface>` per interface (D-8): `iface`, the interface number,
  and one entry per live interaction, keyed by the declared name, holding
  `iface`, `ord`, `kind` (`"signal"`, `"event"`, `"command"`, `"query"` or
  `"fixed"`) and the payload codecs of its roles: `payload` for a signal, an
  event and a `fixed`; `request` for a command; `request` and `reply` for a
  query. An entry carries `limit`, the member's payload limit in bytes, when a
  `[limits]` entry of the manifest gives one: its `[limits.interaction]` entry,
  else the entry of its kind in `[limits.kind]`, else `default` clamped to the
  default ceiling of its kind (`Interaction.limit` of the model); absent, the
  member has the default ceiling of its kind. The TypeScript client reads each
  member's limit from these tables
  ([`ridl-transport-ws-ts.md`](ridl-transport-ws-ts.md)). A tombstone has no
  entry. A query with a fallible `T | E` reply has no `reply`. An interaction
  whose payload has no finite bound has no entry, and a comment stands at its
  place. Supported stream interactions have a table entry and an exported
  function, as [D-17 and D-18](#stream-functions) describe. Unsupported forms
  have no entry or function, and a comment states the specific reason.

An `internal` payload type is listed in `PAYLOAD_TYPES`, so that the list equals
the package's part of `WASM_PAYLOAD_TYPES`, but gets no `encode` or `decode`,
because `<base>.ts` does not export its type; an interaction whose payload type
is internal is refused (D-2).

The file is written only where it can be used. A package gets one when it has at
least one payload root that gets a codec, local or foreign (an interface whose
one payload type is `ridl.std.Name` is enough), or a supported stream call. A
raw-only parameterless stream can therefore cause a codec module to be written
without a named payload root; a package with neither gets no file. The file
imports the builder, `<base>.ts` and `flatc`'s barrel only when it has a local
payload type, because a package without one has no table and `flatc` writes no
barrel for it. `ridl.std` gets a file only when a package's codec file imports
it, for a payload type that is a `ridl.std` scalar; `ridlc` asks the backend
(`codec_imports`, which applies the same predicate as `generate_codec`) before
it writes the standard package's emits. A private `codec<Name>` constant, the
`PayloadCodec` an interface entry holds, is written only for a payload type an
entry names, so that `deno lint` reports nothing unused in the file.

The file starts with the generated marker and header that `<base>.ts` carries,
then `/* eslint-disable */`. Payload functions and tables carry a one-sentence
doc comment; the type's rules stay on the type in `<base>.ts` (D-13). Stream
functions carry model-derived interaction and parameter TSDoc (D-18). The
imports are namespaced (`flatbuffers`, `t` for `<base>.ts`, `fb` for `flatc`'s
output, one alias per foreign package), and every relative import carries the
`.js` suffix (D-15). Ordinary entries import only the runtime's `PayloadCodec`
type when needed and satisfy `MemberRef` structurally. Stream functions also
import the runtime types, errors and adapters described in D-17; they import
nothing from the WebSocket package. The names the file declares are checked
before anything is written, and a second declaration of one is refused with an
error that names both: an interface or an induced tuple named after a reserved
name of the file (`CATALOG_NAME`, `CATALOG_HASH`, `PAYLOAD_TYPES`, `RULES`,
`PayloadCodec`, `RuleError` when the module reaches an enum or an enum set, an
import alias `flatbuffers`, `t`, `fb`, `<package>` or `<package>_codec`), two
enum sets of other packages whose `pack_<alias>_<Name>` or
`unpack_<alias>_<Name>` functions spell the same (`a.b` / `c_d` and `a.b.c` /
`d`), two foreign payload types whose `codec<Package><Name>` constants spell the
same (`a.b` / `C` and `a` / `BC`), and a local payload type whose `codec<Name>`
spells a foreign one. An interaction named `iface` is refused because it
collides with the interface table metadata key of that name; the error names
both sources.

## Stream functions

**D-16. The payload rule table changes together with wasm.** The sorted table is
`length, pattern, range, step, unique, utf8, variant`. Codes are 2 plus the
index: `utf8` is 7 and `variant` is 8. Widening the TypeScript rule union and
moving `variant` from 7 to 8 is a breaking change for the next breaking release.
Regenerate the TypeScript module and wasm codec together. These payload ABI
codes are separate from frame detail codes.

**D-17. A runtime context supplies transport and verification.** Every function
takes `session: StreamSession` first: `{ transport, codec }`, with a loaded
`Codec` and a structural `StreamTransport`. The application connects its
transport and loads wasm explicitly; there is no global codec or hidden load.
The generator calls transport methods with their receiver retained. Generated
imports come only from `@driftsys/ridl-runtime`: `StreamSession`,
`StreamOptions`, `PayloadCodec`, the setup and stream errors, and the needed
`decodeStream`, `decodeTextStream`, `encodeUpload`, `byteUpload` or `textUpload`
adapters. The runtime has no dependency on the WebSocket package.

Discovery resolves the non-stream request, named stream elements and any plain
reply through the same finite FlatBuffers payload roots used by ordinary
entries. It includes induced request/reply tuples and foreign scalar roots.
Before sending, a function checks the codec catalog hash, rejects a zero member
limit, resolves all named payload ids and encodes and verifies its request.
Named input elements are encoded and verified before transmission. Named output
elements and plain replies are verified before decoding into application values.
Text replies use fatal UTF-8 decoding per chunk; raw bytes pass through.

**D-18. Functions and tables describe the supported stream forms.** The exported
name is `<Interface>_<declaredMember>`, for example `DocStore_fetch`. Non-stream
parameters follow the context in declaration order; the final
`opts: StreamOptions` is required and contains `bound` in milliseconds. The
functions return:

- Reply only: `ReadableStream<T>`.
- Command with one upload:
  `{ upload: WritableStream<T>, accepted: Promise<void> }`.
- Query with one upload and a plain reply:
  `{ upload: WritableStream<T>, reply: Promise<R> }`.
- Query with one upload and a streamed reply:
  `{ upload: WritableStream<T>, stream: ReadableStream<R> }`.

Here raw bytes use `Uint8Array`, text uses `string`, and a named element uses
its domain type. The table entry retains `iface`, `ord`, `kind`, `request` and
any explicit `limit`; a plain query result adds `reply`. `streams` is an array
of `{ no, form, element? }`: reply 0 precedes parameter 1, `form` is `bytes`,
`text` or `elements`, and only `elements` carries a `PayloadCodec`. The request
contains non-stream parameters only.

The collision checker registers the complete exported function name as well as
`StreamSession`, `StreamOptions`, `CatalogMismatch`, `CodecError`,
`StreamError`, `checkStreamSession`, `encodeStreamRequest`, any
`decodeStreamReply` helper and the adapters the file uses. A collision is a
generation error naming both sources; the generator does not silently rename
public functions. Private parameter and table-capture bindings are allocated
without changing public names.

Stream TSDoc renders the interaction's model doc, links, canonical interaction
rule texts, `@see`, `@since` and `@deprecated`, then model-derived `@param` tags
for non-stream parameters. The `@remarks` Rules list comes from
`Interaction.rules`. Stream-parameter documentation and parameter rules
(`Param.rules`, for both stream and non-stream parameters) are not rendered.
Local domain links name the imported `t` namespace; targets without an emitted
item remain qualified code spans. Private helpers carry no facade docs.

**D-19. Sender adapters preserve the distinction between chunks and elements.**
Raw writes split at the member limit, and text splits only between complete code
points. Text encoding rejects unpaired JavaScript surrogates with the `utf8`
rule. An oversized code point or encoded named element fails locally as corrupt;
a named encoding is never split. Empty byte and text writes remain valid chunks.
Named `bytes` and `string` types remain whole named elements.

**D-20. Local errors are distinct from transport errors.** `StreamError.failure`
is `{ category: "corrupt" }` for malformed bytes, an oversized encoding, or any
other exception a generated `encode` or `decode` throws, or
`{ category: "contract", contract: { category:
"invalid-value", rule } }` for a
constraint or UTF-8 violation, including a `RuleError` a generated `encode` or
`decode` throws. The original exception is kept as the `cause`. Remote errors
retain their original object identity. `CatalogMismatch` and
`UnknownPayloadType` are setup errors before request transmission. `CodecError`
also reports invalid codec ABI or verifier metadata. Normal pipe cancellation
interrupts the raw call when decoding fails; it does not invent an outbound
contract frame. An upload adapter failure errors the local writer with
`StreamError` and aborts the transport. A duplex reply then fails with the
transport's interruption, rather than that local `StreamError`. Explicit upload
abort preserves the supplied reason on the native writer; the other direction
reports transport interruption.

**D-21. Generated interoperability uses the document example.**
`examples/docstore/web` loads the generated wasm and tables, calls byte
put/fetch, checks 64 exact indexed named download chunks, and exercises duplex
exchange. The existing raw transport fixtures remain transport regressions.
`just ts-e2e` generates and builds the example and runs both those regressions
and the generated consumer against Rust. `just ts-browser-e2e` remains the
transport browser regression; the document example has no browser page.

**D-22. Platform behavior is tested by mutation.** Cancellation and backpressure
already provided by platform streams are retained. Their regression tests may
pass initially; production mutations establish that the tests detect broken
forwarding or credit waiting. They are recorded as platform behavior with
mutation evidence, rather than artificial assertion RED runs.

**D-23. Duplex cancellation follows the transport contract.**
[The transport record, D-23](ridl-transport-ws-ts.md), owns the byte transport
state machine: upload abort sends stream-1 then stream-0 interruption and
forgets the call; reply cancel sends stream 0 only. Successful abort lets the
platform error the native writer. Local reply failure and a blocked write use
the transport interruption error. No frame amendment is required.

**D-24. Ordinary fallible queries retain their previous table shape.** A plain
query with an inline `T | E` result still has no `reply` codec entry. Generated
upload queries whose inline fallible result has no codec are explicitly omitted;
a named result union with a finite codec is supported. This does not change
ordinary-call generation.

**D-25. Upload writers retain native close behavior.** Pending and later writes,
`writer.closed`, and a close queued before remote refusal retain the original
remote error. Calling `close()` after the writer is already errored follows
platform `TypeError` behavior. No writer proxy changes those semantics.

**D-26. Query replies are nonempty language values.** The language rejects a
query result `()` with RIDL-105. Generated upload queries support named unions
and induced tuple replies; no synthetic empty-query result is added.

**D-27. Duplex liveness uses an additional echo.** After the first 64 exact
named echoes, the document consumer sends a 65th valid indexed chunk and
requires its echo before upload close, then requires normal reply end. This
establishes continued progress while upload remains open without a timing probe.
The download validator still expects 64 elements.

**D-28. Provider unit tests belong to the Rust test gate.** `just test`
generates the example's Rust API immediately before running the server workspace
tests. That socket-free provider check needs neither `flatc` nor wasm. The web
generation helper compiles and lints the server and runs the web validator
tests; integration mutations therefore reach the generated TypeScript consumer
instead of stopping in provider unit tests.

**D-29. Single-component packages use a separate `flatc` directory.** The codec
module of a single-component package imports `flatc`'s barrel from
`./flatc/<package>.js`, and its domain module from `./<package>.js`. The
document fixture's package name `docstore.api` is no longer needed to keep these
paths distinct; the fixture keeps that name and its generated crate
`docstore_api`. Packages with two or more components keep their existing import
paths. This output-directory rule does not change runtime APIs or wire layout.

The stream fixture `crates/ridl-backend-ts/tests/fixtures/codec-streams` is
checked by `_codec-ts-check`. Rust generator tests cover discovery, metadata,
function names and collisions, all supported return shapes, exact omissions,
TSDoc and deterministic output. Deno tests cover request verification, named and
text decoding, sender splitting, rule failures, remote error identity,
backpressure, cancellation and duplex direction coupling. Compiler integration
tests pin TypeScript/wasm type names and rule codes, including literal payload
codes 7 and 8.

## The conversion rules

`decode<Name>` reads the root with `getRootAs<Table>`, calls `unpack()` and
converts the object API tree to the plain object; `encode<Name>` converts the
plain object to the tree and calls `pack(builder)`. One private `pack<Name>` and
`unpack<Name>` pair is written per declaration a payload type reaches (D-3). The
rule per typl kind (D-4):

| typl kind                       | `flatc` object API form                           | Plain object form                                | Conversion                                                                                                                                                                                                                                                                    |
| ------------------------------- | ------------------------------------------------- | ------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| named scalar as a payload       | `<Name>Box` table, `value`                        | the branded scalar                               | unbox or box                                                                                                                                                                                                                                                                  |
| named scalar as a field         | the backing scalar                                | the branded scalar                               | a type assertion                                                                                                                                                                                                                                                              |
| enum                            | `bigint` field (the `.fbs` width is `long`)       | numeric `enum`; `<Name>Value` for an `open` enum | `BigInt` to pack; to unpack, `unpack<Name>`, which throws a `RuleError` (rule `variant`) for an undeclared value of a strict enum; an `open` enum unpacks an undeclared value to `{ unknown: n }` and refuses one beyond the safe integers; as a payload, through `<Name>Box` |
| enum set                        | integer field (`bigint` for a 64-bit width)       | branded `number` or `bigint`                     | to unpack, `unpack<Name>`, which throws a `RuleError` (rule `variant`) for an undeclared bit of a strict set; an `open` set keeps every bit and refuses a value outside its width on encode (rule `range`); as a payload, through `<Name>Box`                                 |
| struct                          | `<Name>T` class                                   | `interface` with named fields                    | field by field; the `flatc` member is the lower camel case of `snake_case(declared)`, with the `_` `flatc` appends to a TypeScript keyword (`default_`, `new_`, `class_`)                                                                                                     |
| optional field                  | `null` when absent                                | absent property                                  | `null` to absent, absent to `null`; an optional array, bytes or map field packs as `[]` when absent and reads back as present (known gaps)                                                                                                                                    |
| union                           | `<Name>T { valueType, value }`, scalar arms boxed | `{ kind, value }`                                | `kind` is the arm's declared name; a boxed arm is unboxed                                                                                                                                                                                                                     |
| tuple                           | positional `field_1, field_2, …`                  | object with the declared field names             | position to name, from the model's tuple fields                                                                                                                                                                                                                               |
| array                           | `T[]`                                             | `readonly T[]`                                   | element by element; an optional element, map key or map value is refused, as the Rust codec refuses it                                                                                                                                                                        |
| map                             | `<path>EntryT[]` with `key` and `value`           | `ReadonlyArray<readonly [K, V]>`                 | entry to pair and pair to entry, in order                                                                                                                                                                                                                                     |
| string, bytes, boolean, float   | `string`, `Uint8Array`, `boolean`, `number`       | the same                                         | none                                                                                                                                                                                                                                                                          |
| induced tuple of an interaction | positional table named `InducedName.wire`         | `interface <InducedName.rust>`                   | as a tuple                                                                                                                                                                                                                                                                    |

The `.fbs` enum width stays `long`; narrowing it is driftsys/ridl#1020, and the
converters absorb that change when it lands.

`decode<Name>` does not verify a constraint, and `encode<Name>` does not check
one (D-11): the checks run in the generated Rust, compiled into the wasm module
(ADR-0020 decisions 2 and 7). The one check `decode<Name>` makes is the declared
values of a strict enum and the declared bits of a strict enum set, because the
converter has to produce a typed value: it throws a `RuleError` whose `rule` is
`variant` for an undeclared value or bit, and a strict enum with no zero member
reports a value the buffer leaves out as absent. An `open` enum keeps an
undeclared value, decodes an absent value to its zero member when it declares
one and to `{ unknown: 0 }` when it does not, and throws the same `variant`
error only for a value beyond the safe integers. `decode<Name>` is for bytes the
codec has verified. `encode<Name>` builds what it is given, so that a payload
the codec rejects can be built. A checking constructor for TypeScript is
driftsys/ridl#923.

## Foreign declarations (D-14)

- A payload type that reaches a struct, a union or an enum of another package is
  refused, with a message that names the payload type, the field, arm or element
  (or the interaction) that reaches it, and the foreign declaration.
- A foreign named scalar at a field, arm or element position is converted by a
  type assertion; a foreign enum set is converted by a function of the file that
  checks the value (a strict set refuses an undeclared bit on read, an `open`
  set refuses a value outside its width on encode). The file imports that
  package's `.js` module as a type namespace.
- A foreign named scalar or enum set used as a payload root goes through its own
  package's codec file, because its `<Name>Box` table exists only in that
  package's schema: the file imports `./<package>.codec.js` and its table entry
  calls that module's `encode<Name>` and `decode<Name>`.

`ridl.std` declares named scalars and regex constants only, so a payload that
uses a `ridl.std` type is not refused.

## The wasm type id is resolved by name

`WASM_PAYLOAD_TYPES` is sorted over every package of the crate and `ridl.std`,
while the codec file is generated per package, so a per-package file cannot
compute an index into it (D-5). The file carries qualified names instead, and
the wasm module has one export more:

| Export                                    | Behaviour                                                                                               |
| ----------------------------------------- | ------------------------------------------------------------------------------------------------------- |
| `ridl_type_id(name_ptr, name_len) -> i32` | the index in `WASM_PAYLOAD_TYPES` of the UTF-8 name at `name_ptr`, or -1 when the list does not hold it |

The export is additive. A native `type_id_of(name: &str) -> i32`, under
`#[doc(hidden)]`, is compiled for every target so that a native test checks the
same lookup.

The qualified name is `<package>.<declared name>` for a declaration and
`<package>.<InducedName.rust>` for an induced tuple, in both backends (D-6).
`crates/ridlc/tests/codec_table.rs` pins the agreement: for cabin it compares
`PAYLOAD_TYPES` and `RULES` with `WASM_PAYLOAD_TYPES` and `WASM_RULES`, and for
a two-package fixture it checks that each package's list is an in-order
subsequence of the crate's list and that their concatenation equals it.

`loadCodec` in `@driftsys/ridl-runtime` takes an optional
`payloadTypes: readonly string[]`, resolves every name through `ridl_type_id` at
load, and throws `UnknownPayloadType` naming the first name the module does not
know (D-7). `Codec.typeId(name)` returns the cached id, resolves a name not
given at load on first use, and throws `UnknownPayloadType` for an unknown name.
`verify(typeId, bytes)` is unchanged. A module without the export is a
`CodecError` that names it.

## The manifest option

```toml
[backend.rust]
encodings = ["flatbuffers", "proto3"]

[backend.typescript]
codec = true
```

`codec` is a boolean on a backend table; any other value is MANI-015. `ridlc`
passes it as `BackendOption { key: "codec", value: "true" }` to the backend
whose table carries it; the TypeScript backend accepts it, and a backend that
does not take it refuses it. The codec file is meaningful only against the wasm
module, so `codec = true` implies the wasm codec (D-12):

1. `[backend.rust]` writes no `wasm` key: `ridlc` passes `wasm` to the Rust
   backend with the value `implied`, as if the manifest had written
   `wasm = true`.
2. `[backend.rust]` writes `wasm = false`: MANI-019, an error on the `codec`
   value that names both keys.
3. There is no `[backend.rust]` table: MANI-019, with a message that says there
   is no Rust crate to build the module from.
4. An implied `wasm` whose `[backend.rust] encodings` does not name
   `flatbuffers` is refused by the Rust backend with a message that says the
   module was implied by `codec = true`.

The reverse does not hold: a crate with the wasm module and no codec file is a
valid build. `codec = true` does not require `--emit flatbuffers` in the same
build; the catalog hash checked at load catches a module from another compile.

## `flatc` and the import paths

`ridl` does not run `flatc` (D-10). For a package with two or more name
components, the user runs `flatc --ts --gen-object-api -o <dir> <base>.fbs` with
`<dir>` the directory of the TypeScript emit. The codec file imports `flatc`'s
barrel at `./<package segments joined by '/'>.js` (`./veh/cabin.js` for
`veh.cabin`). For a single-component package, the codec file imports the barrel
at `./flatc/<package>.js` (`./flatc/single.js` for `single`), and the user runs:

```sh
mkdir -p <dir>/flatc
flatc --ts --gen-object-api -I <dir> -o <dir>/flatc <dir>/<package>.fbs
```

The domain module stays at `./<package>.js`, so `flatc` does not overwrite it.
When the codec file imports another package's codec file, `flatc` runs on that
package's `.fbs` too, with its output directory chosen by the same rule.
`flatbuffers` and `@driftsys/ridl-runtime` are bare specifiers that the user's
import map or `package.json` resolves.

## Frozen surfaces

Under [ADR-0029](../decisions/ADR-0029-stability-policy.md), the `manifest`
surface gains the `codec` key, and `diagnostics` gains MANI-019; both are
additions. The codegen protocol does not change: `BackendOption` carries the
key. The TypeScript emit and `@driftsys/ridl-runtime` are not frozen surfaces.

## Known gaps

- Calls with two or more parameter streams are explicitly omitted
  (driftsys/ridl#1224). Inline fallible upload replies without a codec and
  payload roots without a finite FlatBuffers bound are also omitted with a
  reason. Existing refusals for internal payloads and foreign composite roots
  remain. Unsupported stream members are never emitted as ordinary calls.
- The domain type generator still refuses stream types as ordinary typl values;
  only interaction-position streams have generated functions.
- An absent optional array, bytes or map field and an empty one encode the same,
  and both decode as the present empty value (`[]` or an empty `Uint8Array`):
  `flatc`'s object API types a vector as `T[]` and its `pack` always writes it,
  so the file cannot leave the field out of the buffer. The generated Rust codec
  keeps absent and empty apart, so a buffer it wrote with the field absent reads
  as empty in TypeScript.
- A foreign struct, union or enum reached from a payload is refused. The
  designed path is to emit self-contained converters for it into the reaching
  package's file from `model.foreign`, with an import of the foreign package's
  `flatc` output.
- The interop fixture is round-tripped without a wasm module; a round trip of
  the fixture through its own wasm build is not written.
