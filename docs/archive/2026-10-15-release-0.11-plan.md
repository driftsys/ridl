# Release 0.11 — scope and plan

**Status:** draft for review.

## 1. Goal

Release 0.11 fixes the defects that a person who writes ridl, runs `ridl`, or
builds the generated Rust crate can meet today. It adds no feature.

A defect is in scope when it does one of these:

- It gives a wrong result and reports no error.
- It stops the tool (a panic or a failed build) on input that `ridl check`
  accepts.
- It is a warning in the output of a documented command, or a statement in the
  README that is out of date (#864, #877).

0.10 is tagged (v0.10.0). The 0.10 design (section 4.4) says 0.11 starts with a
pull request that moves the freeze baselines on purpose. That pull request is
#962.

## 2. In scope

Each item names the issue that holds the full reproduction, the change to make,
and the check that shows it is done. Every fix starts with a test that fails for
the stated reason.

### 2.3 Warnings and documentation

| Issue | Problem                                                                                                                                                                                                          | Change                                                                                                                                                                                                                                                   | Done when                                                                                                                                                                                                                                                                                                                                    |
| ----- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| #864  | `cargo doc` on a generated crate prints `rustdoc::redundant_explicit_links`. A doc link renders as `[Temperature](crate::veh::cabin::Temperature)` even where `Temperature` resolves to the same item by itself. | Render the short form `[Temperature]` when the link text, read as a Rust path, resolves to the target from the module that holds the doc. Keep the explicit form otherwise. `Links` in `ridl-backend-rust/src/docs.rs` must carry the module of the doc. | `cargo doc` on the cabin crate draws no `redundant_explicit_links` warning, and `-D rustdoc::redundant_explicit_links` is added to the `cargo doc` lines of `just demo`. | #877  | The README describes the book as "introduction, reading guide, getting started"; the book has more chapters.                                                                                                     | Replace the list at `README.md` line 70 with a pointer to `docs/book/SUMMARY.md`.                                                                                                                                                                        | The line has no chapter list; `just link-check` and `just doc-path-check` pass.                                                                                                                                                                                                                                                              |

#864 detail. The warning fires only when the link text resolves by itself to the
target, so a text such as `Horn.active` or `Subsystems.CLIMATE` cannot warn and
keeps its explicit path. Inside a nested module (`veh::cabin::cabin`), a name
from the parent module is not in scope unless the generated code imports it, so
the rule must not assume a parent name resolves. The rule that is safe by
construction is: shorten only when the target item is declared in the same
module as the doc and the link text equals its name. This is conservative: a
link that could be shortened but is not still builds without a warning.

## 3. Checks that apply to every item

- Run `just freeze-check`. #880 adds a diagnostic behaviour, #884 and #925
  change `ridl diff` output, and #874 and #919 change the generated crate. If a
  dump changes, the change follows the stability policy (ADR-0029): a break
  carries `!` in the title and gets a heads-up issue on
  driftsys/ridlc-gen-kotlin.
- Do not write "does not close #N" in a pull request body. GitHub reads it as a
  closing keyword. Use `Refs #N` for partial work.

## 4. Order

The items are independent. #962 merges first, so that each later fix shows its
change to a surface against the v0.10.0 baseline. Then #863 and #874 (they stop
the tool), then #919, #880, #884 and #925, then #864 and #877. Items that touch
the same crate can share one pull request when the changes are small: #884 and
#925 are both in `ridl-diff`.

## 6. Alternatives considered

- **Include the transport and codec work (WebSocket, proto3, repr(C),
  streams).** Rejected: decided to come later, and each is a feature, not a
  defect.
- **Include everything labelled `bug`.** Rejected: most open bug issues are
  maintainer debt that a user does not meet.
- **Ship #863 and #864 as a 0.10.x patch.** Not decided. Both are listed in
  their issues as possible patch fixes; a patch release avoids waiting for the
  rest of 0.11.
