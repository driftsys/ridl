# Streams stages 1 and 2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use
> superpowers:subagent-driven-development (recommended) or
> superpowers:executing-plans to implement this plan task-by-task. Steps use
> checkbox (`- [ ]`) syntax for tracking.

**Goal:** Give every carrier of a member's shape its stream entries (stage 1)
and give `ridl-rt` a stream port that `ridl-loopback` implements and
`ridl-rt-conformance` pins (stage 2), as one breaking `ridl-rt` release.

**Architecture:** Stage 1 adds a `streams` list to the catalog descriptor
(`catalog.fbs`), to the codegen model (`model.proto`) and to
`ridl_rt::contract::Member`, and makes a call's request the induced struct of
its non-stream parameters; the IR and the catalog hash do not change. Stage 2
adds two optional port extensions, `StreamCaller` and `StreamHandler`, keyed by
`(call, StreamNo)`, two `Interest` keys and `Transport::Interrupted`;
`ridl-loopback` implements them over its call table with a window of 4 chunks;
the conformance suite gains a `streams` extension. The last task updates the
records the design amends.

**Tech Stack:** Rust (edition 2021, `rust-version` 1.88 for the runtime crates),
planus (`catalog.fbs`, regenerated by `cargo xtask descriptor-codegen`), prost
(`model.proto`), `cargo xtask freeze`.

**Spec:** `docs/wip/2026-10-31-streams-design.md` — sections 2, 3, 4 and the
stage 1 and stage 2 entries of section 9. Ruling numbers (R-n) below are that
document's.

## Global Constraints

- `ridl-rt` stays sans-IO; a port method never waits; caller-supplied buffers
  (ADR-0032 decision 9; ADR-0018 decision 2).
- A stream is keyed by its call: by the `Correlation` on the calling side and by
  the `ClaimId` on the providing side, plus a `StreamNo` (`u8`): 0 names the
  reply stream; `k` from 1 names the `k`-th stream parameter, counting only the
  stream parameters, in declaration order (R-1).
- The port's unit is the chunk, and a port never splits or merges one (R-2). A
  push takes the whole chunk or nothing; the count it returns is `chunk.len()`
  or 0 (R-3). `ridl-loopback` holds `Loopback::STREAM_WINDOW` chunks (4) per
  stream and direction.
- The IR does not change, so no catalog hash changes (design section 4).
- Nothing about pages or fragmentation in the catalog, the descriptor or
  `ridl-rt`.
- ADR-0032 decision 14 is binding: the checker does not change, no diagnostic is
  added or changed, every source keeps the diagnostics it draws today (R-11).
- The stream ports are optional extensions; neither is in `Factory::Runtime`'s
  bound (R-32).
- Breaking `ridl-rt` changes of this plan: `Member` gains `streams` (R-7) and
  `Interest` gains two variants (R-6); everything else is additive (R-32, R-35).
  The runtime crates keep edition 2021 and `rust-version = "1.88"`
  (`just compat-check`).
- Prose in comments, commit messages and records is plain and literal; shipped
  docs and rustdoc name no story id, stage or epic. Commits follow
  `.git-std.toml` (`<type>(<scope>): <description>`; scopes `ridl-rt`,
  `ridl-ir`, `ridl-descriptor`, `ridl-backend-rust`, `ridl`,
  `ridl-rt-conformance`, `ridl-loopback`, `adr`, `docs`).
- Focused crate tests per task; the full gate (`just build`) runs in CI.

## Review Focus

1. A zero-length chunk is a chunk: `push(c, s, &[])` is taken and the receiver
   reads `Pull::Chunk(0)`, never `End` — a proto3 value whose fields hold their
   defaults encodes to no bytes. Test in Task 6.
2. A `Stream` waker registered on a call that is then forgotten, or whose claim
   is settled, is woken, so a task never waits on a stream that can no longer
   change. Test in Task 6.
3. An `abort` or a `push` after the producer's `end` answers `PushError::Ended`
   and the receiver still reads `End`: a late failure cannot turn a complete
   transfer into an interrupted one. Test in Task 6.
4. A catalog descriptor written before `Member.streams` existed verifies, and
   `ridl describe` prints `"streams": []` for every member of it. Test in
   Task 3.
5. A query whose reply is a stream and whose parameter is a stream (`rebalance`)
   has exactly two entries, `no` 0 then `no` 1, in every carrier, and its
   request is the induced struct with no field. Tests in Tasks 2, 3 and 4.

#[must_use] #[derive(Debug, PartialEq, Eq)]
pub enum Pull { Chunk(usize), End, Pending, Failed(CallError) }
#[non_exhaustive] #[derive(Clone, Copy, Debug, PartialEq, Eq)]
pub enum PushError { TooLarge { cap: usize }, Ended, Failed(CallError), Contract(Contract), Detached }
pub trait StreamCaller: Caller {
    fn pull(&mut self, c: Correlation, s: StreamNo, out: &mut [u8]) -> Result<Pull, ReadError>;
    fn push(&mut self, c: Correlation, s: StreamNo, chunk: &[u8]) -> Result<usize, PushError>;
    fn end(&mut self, c: Correlation, s: StreamNo) -> Result<(), PushError>;
    fn abort(&mut self, c: Correlation, s: StreamNo, e: CallError) -> Result<(), PushError>;
}
pub trait StreamHandler: Handler {
    fn pull_claim(&mut self, claim: ClaimId, s: StreamNo, out: &mut [u8]) -> Result<Pull, ReadError>;
    fn push_claim(&mut self, claim: ClaimId, s: StreamNo, chunk: &[u8]) -> Result<usize, PushError>;
    fn end_claim(&mut self, claim: ClaimId, s: StreamNo) -> Result<(), PushError>;   // REPLY_STREAM: settles Ok(&[])

}
pub enum Interest { Outcome(Correlation), Slot, Event(InterfaceNo), Claim(InterfaceNo),

// ridl_rt::error
pub enum Transport { Timeout, Undelivered, Down, Corrupt, Busy, Interrupted }
// ridl_rt::correlate — one Stream waker per (slot, StreamNo), stored with the call like Outcome
impl<const N: usize> Table<N> {

    pub fn take_stream(&mut self, c: Correlation, s: StreamNo) -> Option<Waker>;

}

**Interfaces:**

- Produces: `pub const STREAM_WINDOW: usize = 4` on `Loopback`;
  `impl StreamCaller + StreamHandler` on `Loopback<E>`, `StreamCaller` on
  `CallerHandle<E>`, `StreamHandler` on `HandlerHandle<E>`.

Rules the implementer applies, fixed by the design: a stream `s` of a call
exists from the first `push`, `push_claim`, `end`, `end_claim` or `abort*` that
names it, so `pull` of a stream nothing has named yet is `Pending` and `pull` of
an unknown call is `Contract(UnknownInteraction)`; a `StreamNo` is unknown only
when the call is unknown (the loopback holds no member table, so it cannot know
how many streams a member declares — `an_unknown_stream_number_is_unknown`
therefore uses a reclaimed correlation, and the test's doc says why). A chunk
longer than the member's limit (`admit`, as `settle` uses it) is `TooLarge`. A
window holds `STREAM_WINDOW` chunks per stream and direction; a push into a full
window answers `Ok(0)`. `end_claim(_, REPLY_STREAM)` is `settle(Ok(&[]))`;
`settle(Err(e))` and `abort_claim(_, 0, e)` record `e` on the reply stream;
`forget` records `Transport::Interrupted` on every stream of the call. Wakers:
`Stream(c, s)` by a push, an end, an abort or a freed window on `(c, s)` and by
`forget` or the settlement of the call; `ClaimStream(claim, s)` by the same on
the provider's side; all woken after the lock is released, like every other
waker.
