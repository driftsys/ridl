# Release 0.10 — the first release with frozen surfaces

Status: design, written 2026-10-11 after a brainstorming session with Sebastien.
Every decision in section 2 is his. The plan that executes this design is
written after this document is approved.

## 1. Goal

0.10.0 is the first release that people adopt for real work. A user who builds
on 0.10.0 can upgrade to any 0.10.x release without changing a source file, a
manifest, a script that calls the CLI, a codegen plugin, a program that uses the
generated Rust crate, or a deployed peer.

To make that true, 0.10.0 must:

1. land every breaking change that is still pending on a surface it freezes;
2. fix every bug and every debt item that a user can see;
3. ship the developer-experience work and the authoring skill;
4. freeze the public surfaces with a check in `just build`, not only with a
   written promise;
5. respect the WebSocket and payload format decisions in
   `docs/wip/2026-10-06-ws-and-payload-formats-steering.md` (decisions A to H).

Success criterion: on the 0.10.0 tag, `just build` runs a freeze check over
every surface in section 3, and each check compares against `v0.10.0`.

Not frozen, and stated as such in the stability policy:

- size and budget values (for example the header sizes of #718 and the sums of
  #852);
- the text of a diagnostic message, of a doc comment and of generated docs;
- anything that is only added: a new subcommand, flag, key, lint, field, tool,
  feature or transport default;
- a new lint, which must start at the `allow` or `info` level;
- internal crates that are not published (`xtask`, `ridlc-gen-model`,
  `ridlc-gen-rust`).

## 4. The freeze mechanism

### 4.1 Why the existing snapshots are not enough

The workspace has 162 insta snapshots. A pull request can rewrite any of them
with `cargo insta accept`, in the same change that breaks the surface. A freeze
gate must compare against a version that the pull request cannot edit.

### 4.2 The check

One recipe, `just freeze-check`, is a member of `build` and of the `expected`
list in `gate-parity`, and CI runs it (ADR-0009).

- `freeze/surfaces.toml` has one row per frozen surface. Each row names the
  surface and a `baseline` git ref. A surface without a row is not checked.
- `cargo xtask freeze dump <surface>` writes the surface as sorted lines of
  text, one fact per line (table in 4.3).
- For each row, the check produces the dump at `HEAD` and at the baseline ref,
  and fails if a line of the baseline dump is missing from the `HEAD` dump. An
  added line passes. A changed line is a removed line plus an added line, so it
  fails.
- For the Rust crates, the check runs
  `cargo semver-checks --baseline-rev
  <ref>` instead of a line dump, because a
  line dump cannot classify a Rust API change correctly (for example a new
  required method on a public trait). The generated crate is checked with
  `cargo semver-checks --baseline-root` against the crate that the baseline ref
  generates from the same sources.

### 4.3 What each dump contains

| Surface                         | One line per                                                                                                                               | Produced from                                    |
| ------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------ |
| Keywords                        | reserved word and its language                                                                                                             | `ridl-syntax` keyword registry                   |
| Accepted sources                | source file of a frozen corpus that compiles without an error (the `docs/book/` fences, `examples/`, the `evals/` corpus)                  | the checker                                      |
| Manifest                        | key path and value type                                                                                                                    | the manifest loader                              |
| Diagnostics and lints           | `CODE lint-name default-level`                                                                                                             | the catalogue                                    |
| CLI                             | `ridl <subcommand> --flag <value-kind>`, exit code, key path of the JSON and SARIF outputs                                                 | clap introspection and the output types          |
| Codegen plugin protocol         | JSON field path and type, for `ridl.ir.v2` and `ridl.codegen.v1`                                                                           | the `ridl-ir` types                              |
| MCP tools                       | tool name and schema path                                                                                                                  | `tools.json`                                     |
| Wire format                     | frame vector (`input → hex`), catalog hash vector (`source → hash`), line of the emitted `.proto` and `.fbs` for the corpus, encoding name | the frame specification, `ridl-ir`, the backends |
| Runtime crates, generated crate | —                                                                                                                                          | `cargo semver-checks`                            |
| Minimum Rust version            | crate and its `rust-version` and `edition`                                                                                                 | the published manifests                          |

### 4.4 Approved breaks

- Before 0.10.0: a pull request that moves the `baseline` ref of one surface.
  Its title carries `!`. It merges only on Sebastien's explicit "merge".
- At 0.10.0: the release pull request moves every baseline to `v0.10.0`.
- During 0.10.x: no break. The only exception is a security fix, recorded in the
  stability policy with its reason.
- 0.11 starts with a pull request that moves the baselines on purpose.

### 4.5 The stability policy

A new decision record, ADR-0029, holds the policy (ADR-0028 is taken by spec
2b). It states the frozen surfaces of section 3, the not-frozen list, the rules
of 4.4 and the table of gates. It cites the stability statements that exist
today and becomes the one place that owns them: the IR specification §6 and §7,
ADR-0021 decision 10, ADR-0025, ADR-0005 §7, and the plumbing-grade stability of
ADR-0008 decision 9. The book gains a **Stability** chapter that states the
policy for users.

## 5. Lanes

Each lane is one session working in its own worktree from `origin/main`. A lane
claims an issue with a comment before it starts work on it. Sebastien merges.
When a lane is done it records its state in a memory file, as earlier lanes did.

### 5.1 Lane 0 — release and policy (this session)

1. Release 0.9.0 from `main` (#851 is breaking). Post upgrade notes for the
   xflux consumers.
2. Write ADR-0029 with an empty gate table, and add `just freeze-check` with one
   fixture that proves a removed line fails and an added line passes. First

## 6. The 0.10.0 release

The release happens when all of these are true:

1. Every surface of section 3 has a row in `freeze/surfaces.toml`.
2. Lanes B and D have no open issue. The internal debt is carried to 0.10.x
   explicitly.
3. `docs/wip/` holds no document for work that 0.10.0 contains: the steering
   note, the devex brief, the 1b design and this design are gardened. A document
   that stays (for example the concept note) has its disposition in
   `docs/wip/README.md`.
4. The book has a **Stability** chapter and a **Migrating from 0.8 to 0.10**
   chapter.
5. The release pull request moves every baseline to `v0.10.0`. Then
   `git std
   bump`, the tag, the crates published, the editor extension
   released as `editor-v0.10.0`, and `install.sh` checked against it.
6. Heads-ups are posted to driftsys/ridlc-gen-kotlin and to the xflux consumers.
7. The 0.10.x queue is posted on the tracker: #265, then #718; #264, which adds
   a plain `connect`; #317; then the internal debt.

## 7. Alternatives considered

- **Ship WebSocket and proto3 in 0.10.0.** Users would have a network transport
  on the first day, but the release would wait for two large lanes. Rejected for
  R-1: the surfaces they plug into are what must not change, and the transport
  and codec can then arrive without a break.
- **Freeze the wire format except the WebSocket binding.** Faster, but a
  WebSocket user would get no wire promise in 0.10. Rejected for R-3.
- **Leave the attribute registry out of the freeze.** Cheaper, but an attribute
  key that compiles on 0.10.0 could become an error on 0.10.x. Rejected for R-4.
- **Only the major bugs.** Rejected for R-5: the release is the one people
  adopt, so what they see must be fixed.
- **Hold all releases until 0.10.0.** One break for users, but consumers would
  stay on 0.8.0 for the whole period and would not see the breaks coming.
  Rejected for R-7.
- **Sequencing by stages** (all breaks, then freeze, then fixes). Simple, but
  serial. **Parallel lanes with a cut-off date.** Fast, but nothing enforces the
  freeze. Both rejected for R-8.
- **Freeze through the existing snapshots.** Rejected in 4.1: the change that
  breaks a surface can also accept the new snapshot.
