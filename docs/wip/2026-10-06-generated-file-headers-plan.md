# Generated-file marker and licence header — implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use
> superpowers:subagent-driven-development (recommended) or
> superpowers:executing-plans to implement this plan task-by-task. Steps use
> checkbox (`- [ ]`) syntax for tracking.

**Goal:** Every text file that `ridl build` generates begins with an
`@generated` marker, then the project's licence header when `ridl.toml` names
one. The generated Rust crate root also carries a narrow clippy allow list.

**Architecture:** The host composes the marker text and reads the header file.
It carries both values in two new fields of the codegen request (ADR-0020), so
an in-tree backend and a plugin render them with the same helper in
`ridl_ir::codegen`. Each backend applies the helper in its contract
`Backend::generate`, not in its `generate` function, so the backend snapshots of
`generate` do not change and the plugin parity tests stay equal. `ridlc` renders
the same preamble itself for `lib.rs` and `Cargo.toml`.

**Tech Stack:** Rust; prost and pbjson (the request schema); `toml` (the
manifest); insta (snapshots); just (the gate).

**Spec:** `docs/wip/2026-10-06-generated-file-headers-design.md` (issue
driftsys/ridl#746). Read it with this plan.

## Global Constraints

- Marker text, exact: `@generated by ridl from package <pkg>. Do not edit.`,
  where `<pkg>` is the dotted package name (`veh.cabin`), never the file stem.
  No version and no timestamp (Q-1).
- **The marker is the first line of the file and the header follows it.** This
  overrides the order in H-6. Sebastien decided it on 2026-10-06, because
  rustfmt looks for `@generated` only in the first 5 lines.
- Comment syntax: `//` for `.rs`, `.ts`, `.proto` and `.fbs`; `#` for
  `Cargo.toml`. A header line that is empty is rendered as the bare comment
  token (`//` or `#`) with no trailing space.
- No marker in a JSON or binary output: `.codegen.json`, the IR dumps, and
  `.catalog.binfb`. These formats cannot hold a comment.
- The manifest key is `[codegen] header-file`. The path is relative to the
  manifest that declares it. Only the workspace root's manifest (or a standalone
  package's manifest) may set it.
- `lib.rs` allow list:
  `#![allow(clippy::derivable_impls, clippy::module_inception)]`. Add only lint
  names that clippy reports on the cabin crate. Every name must be known to the
  `rust-version` in `crates/ridl-rt/Cargo.toml`, because `compat-check` compiles
  `lib.rs` there with `-D warnings`. Never `allow(warnings)`.
- The overwrite-refusal check accepts the old marker
  (`// Generated by ridlc. Do not edit.`, `# Generated by ridlc. Do not edit.`)
  and the new one.
- New request fields are additive in v1 (IR specification §6): numbers 7 and 8,
  with no change to `SCHEMA`.
- New diagnostic codes: `MANI-011` and `MANI-012`, both `Error`. An `Error`
  needs no edit to the severity test in `diag.rs`.
- Shipped docs and rustdoc name no story or plan (`just story-id-check`). Prose
  is plain and literal.

## Review Focus

1. A header file saved with CRLF line endings, or with trailing spaces: the
   generated files must contain no `\r` and no trailing whitespace. Otherwise
   `prim`, rustfmt and `git diff` report every regeneration as changed. Task 1
   pins this.
2. Regenerating into an output directory that an earlier release wrote, with the
   old `Generated by ridlc` marker: the build must overwrite it, not refuse it.
   Task 4 pins this.
3. A workspace member's `ridl.toml` that sets `[codegen] header-file`: the
   setting must not be ignored without a message. MANI-012 reports it. Task 2
   pins this.
4. Single-file mode (no `ridl.toml`): the marker names the package declared in
   the file, not the file stem, there is no header, and the output still
   compiles when `include!`d. Task 3 pins this.
5. A header file that is empty, or that contains only blank lines: there is no
   header and no stray `//` lines, and the file is the same as when no
   `header-file` is set. Task 1 pins this.

### Task 1: Request fields and the preamble helper

**Files:**

- Modify: `crates/ridl-ir/proto/ridl/codegen/v1/plugin.proto` (`CodegenRequest`)
- Modify: `crates/ridl-ir/src/codegen/contract.rs` (or the module that
  re-exports `SCHEMA`; put the helpers beside `text_file`)
- Modify: `crates/ridlc/src/lib.rs` (`codegen_request`, about L1701)
- Modify: the callers of `codegen_request`:
  `crates/ridlc-gen-rust/tests/parity.rs`,
  `crates/ridlc-gen-model/tests/parity.rs`, `crates/ridlc/tests/layout.rs`,
  `crates/ridlc/tests/codegen_model.rs`
- Test: the `#[cfg(test)]` module of the helpers' file

**Interfaces:**

- Produces:
  - proto: `string generated_marker = 7;` and `string header = 8;`. Their
    comments say: the host composes the marker; `header` is the normalised
    header text, lines joined by `\n`, with no trailing newline, and empty when
    the project sets none; a backend that cannot hold a comment ignores both.
    JSON names: `generatedMarker`, `header`.
  - `pub fn generated_marker(package: Option<&str>) -> String`. `Some(p)` gives
    `@generated by ridl from package {p}. Do not edit.`, and `None` gives
    `@generated by ridl. Do not edit.`. `None` is used only for the crate files
    of a workspace build (Task 4).
  - `pub const GENERATED_MARKER_PREFIX: &str = "@generated by ridl";`
  - `pub fn normalise_header(text: &str) -> Option<String>`: split into lines
    (accept `\r\n`), trim the end of each line, drop leading and trailing blank
    lines, and return `None` if nothing is left.
  - `pub fn comment_preamble(marker: &str, header: &str, comment: &str) -> String`:
    the marker line, then each header line, each prefixed with `"{comment} "`,
    or written as the bare `comment` when the line is empty. Each line ends with
    `\n`, and one blank line ends the preamble. When both `marker` and `header`
    are empty, it returns `""`.
  - `codegen_request(base, package, others, options, deployment, header: Option<&str>)`:
    sets `generated_marker` from `generated_marker(Some(&package.name))` and
    `header` from `header.unwrap_or_default()`.

- [ ] **Step 1: Write the failing tests**

  - `comment_preamble_puts_the_marker_first`:
    `comment_preamble("@generated by ridl from package a.b. Do not edit.", "Copyright X\n\nSPDX-License-Identifier: MIT", "//")`
    equals
    `"// @generated by ridl from package a.b. Do not edit.\n// Copyright X\n//\n// SPDX-License-Identifier: MIT\n\n"`.
  - `comment_preamble_uses_the_hash_token`: with comment `"#"` and an empty
    header, it equals `"# @generated … Do not edit.\n\n"`.
  - `normalise_header_removes_carriage_returns_and_trailing_space`:
    `"A  \r\n\r\nB\t\r\n\r\n"` gives `Some("A\n\nB")`.
  - `normalise_header_of_blank_text_is_none`: `""`, `"\n\n"` and `"  \r\n"` each
    give `None`.
  - `generated_marker_names_the_package`: assert both forms against the exact
    strings above.
  - A round-trip test: a request with both fields set survives `request_to_json`
    and `request_from_json`. A request with `header` empty has no `"header"` key
    in the JSON.

- [ ] **Step 2: Run them and see them fail.**
      `cargo test -p ridl-ir comment_preamble normalise_header generated_marker`
      must fail to compile or fail its assertions.

- [ ] **Step 3: Add the fields and the three functions. Add the `header`
      parameter to `codegen_request` and pass `None` at every existing call
      site.**

- [ ] **Step 4: Run them and see them pass.** Run `cargo test -p ridl-ir`, then
      `cargo test -p ridlc -p ridlc-gen-rust -p ridlc-gen-model`. All pass. The
      parity tests stay green because no backend reads the fields yet.

      `feat(ridl-ir): carry the generated-file marker and header in the codegen request`.
