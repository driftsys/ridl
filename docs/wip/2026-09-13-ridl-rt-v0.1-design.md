## 1. Scope

`ridl-rt` is the `no_std` library that generated code links and a runtime
implements: identity, time and the envelope, samples, the payload traits, the
interaction descriptors, the ports, and the contract and transport errors.

**Version 0.1.0 carries the note's full surface** — every item of §1.1 of the
note except those R-2 lists as left out and three this spec replaces:
`InterfaceId` is renamed `InterfaceNo` (R-3), and `Ack` and `Outcome` become
`Result` types (R-10). E11.1 (the frame), E11.9 (the loopback runtime, which
implements every port) and the three codec stories (E11.7, E11.8, E11.12) are
written against this crate, so they start from 0.1 without waiting for a second
release. A 0.x version permits a breaking 0.2.

Not in `ridl-rt`, by the records: the engine (ADR-0018 amendment, parked as
`ridl-engine`), the runtimes (ADR-0020 decision 6), the codecs (E11.7, E11.8,
E11.12), and the generated faces of the note's §8, which are the Rust codegen's
output.

## 2. Decisions

### R-1 The full surface in 0.1

Decided by Sebastien. Streams (RA-X1) and `Inline` payloads (RA-X7) are out, as
the lanes plan's P-1 states.

### R-2 Module layout: six modules, `strata` renamed `error`

The six modules of ADR-0020 decision 5 stay. The module the note calls `strata`
is renamed `error`: it holds the types of ridl §10's strata 2 and 3, and a
reader of generated code meets `ridl_rt::error::Contract` before reading the
reference's vocabulary. The module documentation cites ridl §10. Errors local to
one module stay beside the traits that return them, as `io::Error` does.
ADR-0020 decision 5 is amended in place in the pull request that carries this
spec (§8).

| Module     | 0.1 contents                                                                                                                                                                                                                                                         |

| `payload`  | `Payload<E>`, `Ref`, `Encoded`, `EncodeError`, `VerifyError`, `Malformed`, `Violation`, `Rule`                                                                                                                                                                       |

### R-3 Identity

```rust
pub struct Ordinal(pub u32);          // per interface: position in the body, 1-based (ridl §11)
pub struct InterfaceNo(pub u32);      // per catalog: the lock-file number, or a provisional one (D-7)
pub struct CatalogHash(pub [u8; 32]); // SHA-256, the catalog hash of rsdl note D-8
pub struct CatalogRef { pub name: &'static str, pub hash: CatalogHash }
#[repr(u8)] pub enum Kind { Signal = 1, Event = 2, Command = 3, Query = 4, Fixed = 5 }
```

**`Ordinal` and `InterfaceNo` are `u32` (gate GW).** Sebastien approved both
widths on 2026-09-13 as section 1 of lane L's lock design, posted on
driftsys/ridl#328. Neither is ever 0. The IR already carries an ordinal as
`uint32` (`crates/ridl-ir/proto/ridl/ir/v2/ir.proto:87`), and the catalog
descriptor plan writes `uint32` for both; the note's `u16` is replaced. Lane L
records one fallback: if E11.1 finds that a frame header must fit in 8 bytes or
fewer, or must carry the numbers in an existing 16-bit transport header field,
these two runtime types become `u16` with a range check at lowering, while the
IR and the descriptor keep `uint32`. That change would reach `ridl-rt` as a 0.x
minor release.

**`CatalogHash` is `[u8; 32]`, SHA-256.** GW does not fix this width: lane L
assigns it to rsdl note D-8 and the runtime descriptors design. The records
disagree — the vocabulary note §6 writes `u64`, the ridl-rt note has a
per-interface `u64` (`2026-09-08-ridl-rt-design.md:469`), and the catalog
descriptor plan on `main` writes SHA-256 over the reduced package, 32 bytes
(`2026-09-13-catalog-descriptor-plan.md:84`, `:327`). `ridl-rt` takes the plan's
width, because the plan is the record that computes the hash, and a generated
`Interface::CATALOG` and a catalog descriptor must carry the same bytes (runtime
descriptors D-10). Decided by the driver under Sebastien's delegation.

- **`InterfaceNo` replaces the note's `InterfaceId`.** The note scopes it "per
  service", which is the service slot model D-7 retires. Under D-7 an interface
  number is scoped by its catalog (package). The name follows D-7's "interface
  number": the value is allocated from the lock file's `next` counter, not an
  opaque identifier. Lane L's GW comment writes `InterfaceId(u32)`; the width is
  the same.
- **`ServiceId` is dropped.** D-7 gives a service no number and keeps it out of
  the routing key; a tag-based transport's service number is that backend's
  attribute (rsdl note D-6). Under RA-26 nothing would produce the type.
- **No catalog slot type.** The slot is per connection, assigned outside
  generated code (D-7, runtime descriptors D-5); generated code never sees it.
- **Provisional numbers are marked in the descriptor, not the type**
  (`Interface::PROVISIONAL`, R-5). A provisional number routes the same way a
  frozen one does, because the build is deterministic; only a runtime's policy
  differs (runtime descriptors D-8), and a flag bit would take a bit of the
  `u32` that GW fixed.
- **`CatalogRef` equality compares the name and the hash.** The D-8 hash is over
  the interfaces, their numbers and the types they reach, and may not cover the
  package name, so two packages with identical contents could share a hash.

`Kind` keeps exactly the five values of the language (RA-04).

### R-4 A port is bound to one catalog

Two packages can each have an interface numbered 1. A port is constructed by the
runtime for one catalog, and every interaction port has one supertrait:

```rust
pub trait Attached { fn catalog(&self) -> &CatalogRef; }
```

Port methods that name an interaction keep `(InterfaceNo, Ordinal, bytes)`, so
RA-13 changes only by the rename of `InterfaceId` (§4). A generated client
compares `port.catalog()` with `Iface::CATALOG` once, when it is constructed,
and refuses a mismatch then rather than on every call. A provider that spans two
catalogs holds one port set per catalog and commits each; nothing atomic is
lost, because the generation is per interface already (ADR-0018 decision 8). How
a runtime attaches a port to a catalog is the runtime's API and is not in
`ridl-rt`.

The identity analysis ran two packages, each with `InterfaceNo(1)` and
`Ordinal(1)`, against one test store per catalog: routing stayed distinct, a
mismatch was refused at construction, and `MEMBER.ordinal` was usable as a
constant pattern.

### R-5 The interaction descriptors

The descriptors are the per-member form of the ordinal table ADR-0013 decision 3
requires, extended with the interface number and the catalog hash (runtime
descriptors D-10). `ridl-rt` depends on no descriptor crate; its fields agree
with the catalog descriptor's D-4 fields by name and meaning.

```rust
pub trait Interface {
    const CATALOG: &'static CatalogRef;
    const NUMBER: InterfaceNo;
    const PROVISIONAL: bool;
    const NAME: &'static str;
    const MEMBERS: &'static [Member];
}
pub trait Interaction { type Iface: Interface; const MEMBER: &'static Member; }
pub trait Signal:  Interaction { type Payload; fn init() -> Self::Payload; }
pub trait Event:   Interaction { type Payload; }
pub trait Fixed:   Interaction { type Payload; }
pub trait Command: Interaction {
    type Args;
    fn require(args: &Self::Args) -> Result<(), Violation>;
}
pub trait Query: Interaction {
    type Args;
    type Reply;
    fn require(args: &Self::Args) -> Result<(), Violation>;
    fn ensure(args: &Self::Args, reply: &Self::Reply) -> Result<(), Violation>;
}

pub struct Member {
    pub ordinal: Ordinal,
    pub kind: Kind,
    pub name: &'static str,
    pub timing: Option<Timing>,           // None: no Timing in the IR (a bare call, a fixed)
    pub payloads: &'static [PayloadInfo], // one per payload; two for a query (D-6)
}
pub enum TimingMode { StrictPeriodic, Range }
pub struct Timing { pub mode: TimingMode, pub min: Option<Duration>, pub max: Option<Duration> }
pub struct PayloadInfo { pub type_name: &'static str, pub max_size: EncodedSizes }
pub struct EncodedSizes { pub proto3: Option<u32>, pub flatbuffers: Option<u32>, pub repr_c: Option<u32> }
```

| `ridl-rt` field                   | Catalog descriptor D-4 field                                           |
| --------------------------------- | ---------------------------------------------------------------------- |
| `CatalogRef::name`, `::hash`      | identity of the catalog: name, catalog hash                            |
| `Interface::NAME`                 | interface name                                                         |
| `Interface::NUMBER`               | the frozen number from the lock file                                   |
| `Interface::PROVISIONAL`          | the `provisional` flag                                                 |
| `Member::name`, `ordinal`, `kind` | member name, ordinal, kind                                             |
| `PayloadInfo::type_name`          | the payload type name, per payload                                     |
| `Member::timing`                  | the bounds and QoS terms the IR carries (the IR carries `Timing` only) |
| `PayloadInfo::max_size`           | the max-size table of D-6, one column per core encoding                |

Not carried, with the reason:

- the toolchain version — not identity;
- retired interfaces and reserved ordinals — a runtime answers
  `UnknownInteraction` for either, and the finer diagnostic is an engine's, read
  from the descriptor;
- the stream element type and flag — streams are out of 0.1;
- `default_applied` — no runtime behaviour depends on it.

Carried by `ridl-rt` and not by D-4, because D-4 carries no values and no
functions: `Signal::init`, `Command::require`, `Query::require` and
`Query::ensure`.

Changes from the note's §5, each with its reason:

- **The associated payload types have no bound.** One bound per encoding cannot
  be written on the trait; a binding writes `S::Payload: Payload<E>` where it
  uses the type. The note's `Encode<Memory>` was a stale name for `Payload<E>`.
- **`min` and `max` are optional for every kind, and the mode is carried.** The
  IR leaves a half-open side unset on a signal as well as on a call: compiled
  with `ridlc build --emit ir-json`, `@[..500ms]` gave only `maxUs`, `@[20ms..]`
  only `minUs`, an untimed signal both with `defaultApplied`, `@10ms` both
  equal, and a bare `command` no `timing` at all. A strict period is a separate
  mode (ridl §9.2). The note's `MIN`, `MAX` and `TTL` constants are replaced:
  TTL is `max` read on an event (ridl §9).
- **`COHERENT` is dropped.** Coherence at the interface grain is implicit and
  never declared (ADR-0015 decision 9).
- **The per-interface `HASH` becomes `CATALOG`.** The hash D-8 defines is per
  catalog.
- **The descriptor data lives in `Member`**, one source for both the constant
  per interaction (`Interaction::MEMBER`) and the table per interface
  (`Interface::MEMBERS`).
- **`Member.max_size` becomes one row per payload with one column per encoding**
  (D-6). A column is `None` where that encoding cannot carry the payload.

### R-6 Time and the envelope; #308

```rust
pub struct Timestamp(pub i64);  // µs since the PTP epoch, TAI (ridl §3.1)
pub struct Duration(pub i64);   // µs
pub struct Envelope { pub stamp: Timestamp, pub seq: u64 }
```

**#308 disposition, decided by Sebastien: duplicate suppression is below the
port.** `Envelope` keeps the two fields of ridl §3.1. On a call, a runtime keys
duplicate suppression on the caller's transport identity plus `seq`, as it
already keeps request and reply correlation internal (§3.1). The guarantee is
written on `Handler` (R-10): `next_claim` presents each delivered call once — a
retransmission of a call already presented is not presented again and receives
the cached acknowledgment, and two calls from different callers are never
merged, even when they carry the same `seq`; `ClaimId` is the key that is unique
per channel. A call lost in transport is presented zero times, and its caller
sees `Transport::Undelivered`. On a claim, `envelope.seq` is unique per caller,
not per channel.

The reference text itself is corrected by the ridl finalization pass (E14.2),
which receives this sentence: _on a call, the sequence number is scoped per
(caller instance, channel), and duplicate suppression keys on the caller's
identity plus the sequence number._

**The envelope under `Init`.** Before the first publication a signal's envelope
is `seq 0`, stamped when the channel is created. A channel with no publication
within `max` then reads as `Init` and `Stale`, which is the correct fact. E14.2
confirms this convention.

### R-7 Provenance, freshness, the sample and the occurrence; #309; RA-X4

```rust
pub enum Provenance { Init, Live, Invalid(Cause) }
pub enum Cause      { Declared, Detected(Detection) }
pub enum Detection  { InvalidValue(Violation), Corrupt }
pub enum Freshness  { Fresh, Stale { by: Duration }, Unbounded }

pub struct Sample<T> {
    pub value: T,
    pub provenance: Provenance,
    pub freshness: Freshness,
    pub envelope: Envelope,
}
impl<T> Sample<T> {
    /// `Live`, and not `Stale`.
    pub fn usable(&self) -> bool;
}

pub struct Occurrence<T> { pub payload: Result<T, Detection>, pub envelope: Envelope }
```

- **`Cause` is inside `Provenance::Invalid`**, replacing the note's separate
  `cause: Option<Cause>`. An invalid sample with no cause, or a live one with a
  cause, cannot be built.
- **RA-X4 is settled.** `Declared` is the provider's own transition (ridl §4.5).
  A detection by the consumer's binding is also an invalid state, because ridl
  §10.2 places `INVALID_VALUE` "at a boundary" and that binding is one.
  `Detection::InvalidValue` is that stratum 2 detection, named after §10.2's
  category and `error::Contract::InvalidValue` because its `Violation` may name
  a length, pattern or variant rule as well as a range (the note's `OutOfRange`
  named only the last; renamed by the driver under Sebastien's delegation);
  `Detection::Corrupt` is a serialization failure, stratum 3 (§10.3).
  **`Implausible` is deleted:** ridl §3.3 declares `plausible` as an acquisition
  obligation and states "failure to correspond is not invalidity"
  (`ridl-language-reference.md:390`). `SignalWriter::invalidate` takes no cause:
  downstream of the provider, every upstream reason is `Declared`.
- **`Freshness::Unbounded`** is the freshness of a signal with no staleness
  bound: `signal lastFault : ServiceFault @[1s..]` is legal
  (`ridl-language-reference.md:1000`) and receives no default `max`
  (`crates/ridl-sem/src/timing.rs:762`).
- **Under a detection, the generated binding substitutes a value** — its own
  last good value, or the init value when it has none — so a sample's value is
  never absent (RA-06, RA-34). The runtime's slot holds the bytes that failed,
  so the binding keeps the copy. How it does so without `alloc` is the Rust
  codegen's question (§7).
- **#309 disposition, decided by Sebastien: an event that fails its check is
  delivered with a marker.** The port stays unvalidated: `EventSource::next`
  returns bytes and the generated binding runs the check (RA-34). The face
  returns `Occurrence<T>`, whose `payload` is `Err(Detection)` when the check
  fails. A silent drop is excluded by ridl §10.3 and §10.4 ("nothing fails
  silently"). Quarantine — withholding the occurrence and recording it — would
  need a consumer-side report path, which 0.1 has no port for. If E14.2 chooses
  quarantine, the `Err` arm is never produced and nothing breaks. E14.2
  receives: _an event payload that violates its typl constraints is delivered to
  the subscriber with an invalid marker and its envelope._

### R-8 Encoding, `Payload<E>`, the proof type, and the errors

```rust
mod sealed { pub trait Sealed {} }
pub trait Encoding: sealed::Sealed + 'static { const NAME: &'static str; }
pub struct FlatBuffers;
pub struct Proto3;
pub struct ReprC;

pub trait Payload<E: Encoding>: Sized {
    const MAX_SIZE: usize;
    /// What a successful check leaves behind: the bytes, an accessor, or a parsed value.
    type View<'a>;
    fn encode<'o>(&self, out: &'o mut [u8]) -> Result<Encoded<'o, Self::View<'o>>, EncodeError>;
    fn verify(buf: &[u8]) -> Result<Self::View<'_>, VerifyError>;
    fn decode(r: Ref<'_, Self, E>) -> Self;
}

/// The result of an encode. Data, not a proof.
pub struct Encoded<'a, V> { pub bytes: &'a [u8], pub view: V }

/// A proof, not a view. Private fields and no public constructor.
pub struct Ref<'a, T: Payload<E>, E: Encoding> { bytes: &'a [u8], view: T::View<'a>, _e: PhantomData<E> }
impl<'a, T: Payload<E>, E: Encoding> Ref<'a, T, E> {
    pub fn verify(buf: &'a [u8]) -> Result<Self, VerifyError>;    // calls T::verify
    pub fn encode(value: &T, out: &'a mut [u8]) -> Result<Self, EncodeError>; // calls T::encode
    pub fn bytes(&self) -> &'a [u8];
    pub fn view(&self) -> &T::View<'a>;
    pub fn into_view(self) -> T::View<'a>;
    pub fn decode(self) -> T;                                     // calls T::decode
}

#[non_exhaustive] pub enum EncodeError { Capacity { needed: usize, available: usize } }
#[non_exhaustive] pub enum VerifyError { Structure(Malformed), Contract(Violation) }
#[non_exhaustive] pub enum Malformed {
    OutOfBounds, Unaligned, MissingRequired, Utf8, Union, TooDeep, TooManyTables, TooLarge,
}
pub struct Violation { pub type_name: &'static str, pub rule: Rule }
#[non_exhaustive] pub enum Rule { Range, Length, Pattern, Variant, Invariant }
```

**Why a `Ref` exists only after a check or an encode.** The trait generated code
implements never returns a `Ref`. `Ref`'s fields are private, and the only
functions that build one are `ridl-rt`'s inherent `Ref::verify` and
`Ref::encode`, which call the generated method and wrap its result. So
`Payload::decode` is reachable only with a proof, and RA-08 holds as the note
wrote it. The note's own §4.1 example did not hold across crates: it has the
generated `verify` call `Ref::of(t)`, which a private constructor forbids.

**Why generated code needs no `unsafe`.** The generic associated type `View`
carries what the check produced, so decoding never re-verifies and never calls
an unchecked root. `View` has no `Copy` bound, because a parsed value holding a
`String` or a `Vec` is not `Copy` (with the bound, such a view fails with rustc
E0277), and `Ref` is therefore not `Copy` either: `Ref::view` lends the view and
`Ref::into_view` moves it out. A codec chooses among three views:

- **the bytes** (`&'a [u8]`), when it reads through its own bounds-checked
  reader;
- **an accessor** over the bytes;
- **an owned parsed value**, when verification parses.

For proto3 the choice is E11.8's. An owned view lets `verify` parse once and
`decode` move the value out, but then `encode` must produce an owned view of the
value it has just encoded, which is a clone. A byte view keeps `encode` free of
that, and `decode` parses the verified bytes a second time without checking them
again. One case remains: a flatc-generated accessor as `View` contains `unsafe`
inside the accessor (`Follow::follow` is an `unsafe fn` in the `flatbuffers`
crate), so RA-21 is scoped to code ridl emits (§4). Whether E11.7 uses flatc
accessors is E11.7's decision.

The payload analysis built this in a scratch workspace: a generated-style crate
under `#![forbid(unsafe_code)]` implemented `Payload` for two encodings — one
with a byte view, one with a parsed view holding scalars only — and
round-tripped both; a crate that tried to build a `Ref` without `verify` or
`encode` failed with E0451.

**Errors.** Every error here is `Copy` and owns nothing. `Violation` and `Rule`
are in 0.1 because they are `VerifyError`'s payload and the argument of
`require` and `ensure` (R-5), and one type across packages is what ADR-0018's
context found missing when the vocabulary was emitted per package. `Encoding` is
sealed: the set of encodings is an ADR decision, not a downstream `impl`
(ADR-0020 decision 1), and sealing later would be a breaking change.

### R-9 Features, `no_std`, `alloc` and `wasm32`

- The crate root carries `#![no_std]` and `#![forbid(unsafe_code)]`, with no
  `extern crate alloc`. `#![no_std]` is itself the check: any `std::` path fails
  to compile.
- **The three features `flatbuffers`, `proto3` and `repr-c` are declared and
  empty in 0.1, decided by Sebastien.** The crate has no dependency in any
  feature combination, and RA-01 holds as written. The marker types and their
  `Encoding` impls do not depend on a feature, so a runtime can name every
  encoding without linking any codec.
- The `flatbuffers` dependency, its version, and the obligation it brings arrive
  with E11.7. Adding an optional dependency under an existing feature is
  additive. The obligation, measured by the payload analysis on `flatbuffers`
  25.12.19: that crate uses `alloc` even without `std` (`src/lib.rs:36`,
  `src/verifier.rs:4,9`), so every final binary that enables the feature must
  define a global allocator — a wasm32 `cdylib` without one failed to link with
  "no global memory allocator found", while `cargo check` of the library alone
  passed. The verifier allocated nothing on success, on a contract error, on a
  missing required field at the root and on a truncated root, and allocated one
  trace entry on a data error inside a present field (`src/verifier.rs:217`).
- **`wasm32`.** Stage A3 adds `-p ridl-rt` to the `just wasm-check` recipe. That
  recipe lives in the `justfile`, which S1 changes, so the edit waits for gate
  G2 as A3 already does.

### R-10 The ports and the two extensions

Every port method returns without waiting (RA-14), names no payload type
(RA-13), and takes no `now` (RA-28). A method that names an interaction carries
`(InterfaceNo, Ordinal)` and bytes; the others take a correlation, a claim, a
watermark set or nothing.

```rust
pub trait Clock { fn now(&self) -> Timestamp; }   // one per runtime; not Attached

pub trait SignalReader: Attached {
    fn read(&self, iface: InterfaceNo, ord: Ordinal, out: &mut [u8]) -> Result<RawSample, ReadError>;
}
pub struct RawSample { pub provenance: Provenance, pub freshness: Freshness, pub envelope: Envelope, pub len: usize }

pub trait SignalWriter: Attached {
    fn set(&mut self, iface: InterfaceNo, ord: Ordinal, bytes: &[u8]) -> Result<(), WriteError>;
    fn invalidate(&mut self, iface: InterfaceNo, ord: Ordinal);
    fn touch(&mut self, iface: InterfaceNo, ord: Ordinal);
    fn commit(&mut self);
}

pub trait EventSource: Attached {
    fn subscribe(&mut self, iface: InterfaceNo, ords: &[Ordinal]) -> Result<(), SubscribeError>;
    fn unsubscribe(&mut self, iface: InterfaceNo, ords: &[Ordinal]);
    fn next(&mut self, out: &mut [u8]) -> Result<Option<RawOccurrence>, ReadError>;
}
pub struct RawOccurrence { pub iface: InterfaceNo, pub ord: Ordinal, pub envelope: Envelope, pub len: usize }

pub trait EventSink: Attached {
    fn raise(&mut self, iface: InterfaceNo, ord: Ordinal, bytes: &[u8]) -> Result<(), RaiseError>;
}

pub trait Caller: Attached {
    fn command(&mut self, iface: InterfaceNo, ord: Ordinal, args: &[u8]) -> Result<Correlation, SendError>;
    fn query(&mut self, iface: InterfaceNo, ord: Ordinal, args: &[u8]) -> Result<Correlation, SendError>;
    fn ack(&mut self, c: Correlation) -> Option<Result<(), CallError>>;
    fn reply(&mut self, c: Correlation, out: &mut [u8]) -> Result<Option<Result<usize, CallError>>, ReadError>;
    fn forget(&mut self, c: Correlation);
}
pub struct Correlation(pub u64);

pub trait Handler: Attached {
    fn serve(&mut self, iface: InterfaceNo, ords: &[Ordinal]) -> Result<(), ServeError>;
    fn next_claim(&mut self, out: &mut [u8]) -> Result<Option<Claim>, ReadError>;
    fn settle(&mut self, claim: ClaimId, outcome: Result<&[u8], Contract>) -> Result<(), SettleError>;
}
pub struct Claim {
    pub id: ClaimId, pub iface: InterfaceNo, pub ord: Ordinal,
    pub envelope: Envelope, pub remaining: Option<Duration>, pub len: usize,
}
pub struct ClaimId(pub u64);

pub trait FixedReader: Attached {
    fn read(&self, iface: InterfaceNo, ord: Ordinal, out: &mut [u8]) -> Result<usize, ReadError>;
}

/// Extension: signals in a walkable store. A runtime may omit it.
pub trait ScannableSignals: SignalReader {
    fn generation(&self, iface: InterfaceNo) -> u64;
    fn scan(&self, marks: &mut [Watermark], out: &mut [Changed]) -> usize;
}
pub struct Watermark { pub iface: InterfaceNo, pub gen: u64, pub seq: u64 }
pub struct Changed { pub iface: InterfaceNo, pub ord: Ordinal, pub seq: u64 }

/// Extension: a runtime that can pin one interface generation across several reads.
pub trait CoherentSignals: SignalReader {
    fn read_coherent(&self, iface: InterfaceNo, ords: &[Ordinal],
                     out: &mut [u8], samples: &mut [RawSample]) -> Result<usize, ReadError>;
}
```

Semantics each implementation presents:

- **`SignalReader::read`** copies the slot into `out` and returns the
  provenance, the freshness and the envelope. The runtime resolves both
  provenance and freshness (RA-33).
- **`SignalWriter`**: `set` stages a value, `invalidate` stages the §4.5
  transition with `Cause::Declared`, `touch` re-affirms without a value, and
  `commit` publishes what is staged under one generation increment and one stamp
  per interface, taken from the runtime's `Clock`. `commit` cannot fail (RA-16).
- **`EventSource::next`** returns occurrences in order; a gap in `seq` is a loss
  (§3.1). An occurrence older than its `max` is discarded inside `next` (ridl
  §5.2, RA-33).
- **`Caller::ack`** reports a command's delivery acknowledgment (ridl §6.1):
  `Ok(())` accepted, `Err(CallError::Contract(_))` negative acknowledgment,
  `Err(CallError::Transport(Transport::Undelivered))` no acknowledgment within
  the bound. On a query correlation it returns `None`; the outcome is `reply`.
  The acknowledgment never reaches a generated command method's return value
  (RA-17).
- **`Handler`** presents each delivered call **once** through `next_claim`: a
  retransmission of a call already presented is not presented again and receives
  the cached acknowledgment, and calls from two callers are never merged, even
  with the same `seq`; `ClaimId` is unique per channel (#308, R-6). Every claim
  is settled. For a command, the generated dispatch settles `Ok(&[])` — the
  acceptance — after the arguments and `require` pass and before application
  code runs (ridl §9.3: the bound covers admission, not execution). For a query,
  it settles with the reply bytes, or with the `Contract` error.
- **`FixedReader::read`** copies out, as every read does.
- **A `Short` error does not consume.** `next`, `next_claim` and `reply` return
  `Result<Option<_>, ReadError>`, so a caller that receives
  `ReadError::Short { needed }` resizes and reads the same item again.

Changes from the note's §6, each tied to the inconsistency it fixes:

- `generation` and `scan` leave `SignalReader`: the note's §6.1 had already
  moved them to `ScannableSignals` and left the §6 listing unchanged.
- `RawSample` gains `freshness` (its comment and RA-33 said it had one; the
  struct did not) and loses `cause` (now inside `Provenance`).
- `Claim.kind` is dropped: the descriptor at `ord` gives the kind, so a claim
  for a command and a claim for a query stay distinct (RA-15) without a kind
  field.
- `Claim.remaining` is `Option`: an RPC bound may be absent (ridl §9.3).
- `Busy` leaves `Transport`: flow control is not a stratum 3 failure, so it
  appears only on the submission errors `SendError` and `RaiseError`.
- `Ack { Accepted, Rejected(Contract), Undelivered(Transport) }` becomes
  `Result<(), CallError>`, which removes the nested `Undelivered(Transport)`.
- `Outcome { Ok, Rejected, Failed }` becomes `Result<&[u8], Contract>`, and
  `Failed` is deleted: a stratum 1 failure travels in the reply bytes (ridl
  §10.1), and stratum 3 belongs to the runtime.
- `FixedReader::read` copies out instead of returning `&[u8]` borrowed from the
  runtime: a borrowed buffer is a mechanism, which the note's §6.1 test places
  outside the core.
- `Caller::command` and `Caller::query` return `SendError`, not `CallError`: a
  submission fails locally (`Busy`, `TooLarge`, `Detached`, an unknown
  interaction), while `CallError` is kept for the outcome that `ack` and `reply`
  report.
- `ReadError::UnknownInteraction` becomes `ReadError::Contract(_)`, so the
  stratum 2 category is defined once, in `error::Contract`.
- `Transport` loses `Detached`, which is local to the port and sits on each port
  error, and gains `Corrupt`, the serialization failure of ridl §10.3.
- The note's port-level `Occurrence` is renamed `RawOccurrence`, because
  `sample::Occurrence<T>` is the decoded carrier of R-7.
- `EventSource::next`, `Handler::next_claim` and `Caller::reply` wrap their
  `Option` in `Result<_, ReadError>`, so a `Short` error does not consume.

Both extensions keep the note's §6.1 placement and semantics. Where that wording
returns `Err(UnknownInteraction)`, 0.1 returns
`Err(ReadError::Contract(Contract::UnknownInteraction))`. RA-X2: no port reads
`Family`, and `Family` is not in 0.1 (R-2).

### R-11 The `error` module and the port errors

```rust
// error::
pub enum Contract  { InvalidValue(Violation), PreconditionFailed, ContractBroken, UnknownInteraction }
pub enum Transport { Timeout, Undelivered, Down, Corrupt }
pub enum CallError { Contract(Contract), Transport(Transport) }

// port::
pub enum ReadError      { Short { needed: usize }, Contract(Contract), Detached }
pub enum WriteError     { TooLarge { cap: usize }, NotOwner, Detached }
pub enum RaiseError     { Busy, TooLarge { cap: usize }, NotOwner, Detached }
pub enum SendError      { Busy, TooLarge { cap: usize }, Contract(Contract), Detached }
pub enum SubscribeError { Contract(Contract), Detached }
pub enum ServeError     { Contract(Contract), NotOwner, Detached }
pub enum SettleError    { UnknownClaim, TooLarge { cap: usize }, Detached }
```

`Contract` is ridl §10.2's four categories; `Transport` is §10.3's detected
infrastructure failures, `Corrupt` included. `Detached` — the runtime behind the
port is gone — is local to the port, not a stratum. `SubscribeError` and
`ServeError` carry `Contract` because an unknown interaction fails at bind time
on pub/sub (§10.2). `SettleError::UnknownClaim` covers a claim already settled
or never issued.

### R-12 The release policy

- **Version.** `crates/ridl-rt/Cargo.toml` sets `version = "0.1.0"` itself and
  does not inherit the workspace version. Every other crate stays at 0.0.0
  (P-1). Decided by Sebastien.
- **git-std is unchanged.** git-std 0.11.15 bumps one crate of a workspace only
  with `monorepo = true`. With an explicit `[[packages]]` list naming only
  `ridl-rt`, that mode versions and tags `ridl-rt` alone, in addition to the
  root version bump (git-std `docs/CONFIG.md`, `[[packages]]`; `docs/SPEC.md`
  §2.3.3). It is still a change to `.git-std.toml`, a file lane A shares with
  other lanes (lanes plan §6), made for one release whose version and tag are
  set by hand in less time; it is reconsidered when a second crate publishes.
- **The tag is `ridl-rt@0.1.0`.** It is git-std's default per-package tag
  template (`{name}@{version}`), so a later switch to monorepo mode keeps the
  tag names. The repository has no version tags yet, and `.git-std.toml`'s
  `tag_prefix = "v"` does not match this tag. Decided by Sebastien.
- **Sebastien creates the tag and runs `cargo publish`**, from the maintainer
  checklist of the A4 pull request. No agent runs either (ADR-0007 decision 14,
  the lanes plan §7).
- **crates.io metadata**: `description`; `readme = "README.md"`; `keywords`;
  `categories = ["no-std", "encoding"]`; `license` and `repository` inherited
  from the workspace (MIT, `https://github.com/driftsys/ridl`); and
  `rust-version = "1.95.0"`, equal to the `rust-toolchain.toml` channel.
- **The name is free.** `ridl-rt` returned 404 from the crates.io API on
  2026-09-13. For reference: `ridlc` is reserved by this repository at 0.0.0,
  and `ridl` belongs to an unrelated crate.
- **The crate README** says that 0.x permits a breaking change in 0.2, and lists
  what 0.1 leaves out: streams, `Inline`, the three codecs, `Encoding::FORMAT`,
  `Family`, `Access`, `Constrained`, the runtimes (`ridl-loopback`,
  `ridl-transport-ws`), and the engine.
- **Dry run.** Stage A4 runs `cargo publish --dry-run -p ridl-rt`. If that check
  becomes a `just` recipe, it stays out of `build`, as `release` does, because a
  recipe in `build` must also run in CI (ADR-0009).

## 4. The note's rules whose wording changes

- **RA-11** — "every timing const comes from the IR" becomes "every timing field

## 5. Testing

Every test lives in `crates/ridl-rt` and adds no dev-dependency.

- **E11.0's done-when.** An integration test — a separate crate that links
  `ridl-rt` — hand-writes one catalog, one signal descriptor, a `Payload<E>` for
  a small scalar with `View = &[u8]`, and an in-memory `SignalReader`. It reads
  `Sample<T>` through `SignalReader::read`, `Ref::verify` and `Ref::decode`, and
  asserts `Init`, then `Live`, then `Invalid(Declared)`, and `Stale` once `max`
  has passed. A copy under `examples/` shows the same program to a reader.
- **The proof holds.** A `compile_fail` doctest shows that code outside the
  crate cannot build a `Ref` without `Ref::verify` or `Ref::encode` (E0451).
- **Unit tests.** `Sample::usable` over every provenance and freshness,
  `Unbounded` included; `CatalogRef` equality requires both the name and the
  hash.
- **Object safety.** Each port trait is used as `&dyn` in a test, so a later
  signature that breaks `dyn` use fails the build.
- **Gates.** `just build` passes; `just wasm-check` covers `ridl-rt` (R-9).
