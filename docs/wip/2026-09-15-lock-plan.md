# The lock file and `ridl lock` — implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use
> superpowers:subagent-driven-development (recommended) or
> superpowers:executing-plans to implement this plan task-by-task. Steps use
> checkbox (`- [ ]`) syntax for tracking.

**Goal:** Give every interface a number from a per-package `interfaces.lock`,
add `ridl lock` and its git merge driver, make `ridl diff` match interfaces by
number, refuse unrecorded numbers at publication, and retire the service slot
model with RIDL-146, RIDL-147 and RIDL-148.

**Architecture:** A pure line-table parser in `ridl-core` (compiled without the
`fs` feature) reads `interfaces.lock`. The loader attaches the parsed file to
the salsa `Package` input, so the one tracked `check_package` writes each
interface's `number` and `provisional` flag into the IR for `ridlc`, `ridl` and
the language server alike. The `ridl` facade gains `ridl lock` (allocation,
rename, retire, merge), runs its desk check when RIDL-409 is the only error, and
refuses a provisional or dropped number inside the RIDL-408 publication gate.
`ridl-diff` replaces the name-keyed interface walk and the service slot walk
with a number-keyed walk and a service set.

**Tech Stack:** Rust, one cargo workspace, `--locked`. Diagnostics are declared
through `diag_codes!` in `crates/ridl-core/src/diag.rs`; diff categories through
`declare_categories!` in `crates/ridl-diff/src/lib.rs`. The IR is
`crates/ridl-ir/proto/ridl/ir/v2/ir.proto`, compiled at build time by
`prost-build` and `pbjson-build` with `emit_fields()`. Integration tests drive
`CARGO_BIN_EXE_ridl` and `CARGO_BIN_EXE_ridlc` through `std::process::Command`;
snapshots use `insta`.

**Spec:** [`2026-09-13-lock-design.md`](2026-09-13-lock-design.md) (merged as
driftsys/ridl#334). Read it before any task. Its line citations were written
before pull requests #330, #331 and #327 merged, so this plan cites code by
function name, and the tasks give the current locations.

## Global Constraints

- **One branch, one pull request.** Stage L4 runs every task below on branch
  `feat/ridl-lock` in `.claude/worktrees/lane-l-lock`, created from
  `origin/main`, and opens one pull request. Each task is one or more commits.
  Run `git branch --show-current` before every commit and every push. Before a
  rebase, compare `git ls-remote origin feat/ridl-lock` with the local head and
  read `git reflog -8`.
- **Gates.** L4 starts only when G1 and G2 of the lanes plan §5 hold (checked
  with the commands there). Both held on 2026-09-15.
- `just build` passes after every task. Every cargo command passes `--locked`.
  Run one test with `cargo test -p <crate> --locked <test_name>`.
- `cargo fmt --all` before every Rust commit; `just fmt` before every Markdown
  commit.
- Conventional Commits, linted by git-std against `.git-std.toml`. The scopes
  this plan uses are `ridl-ir`, `ridl-core`, `ridl-sem`, `ridl-diff`, `ridl`
  (the facade binary and the language), `adr` and `docs`. A commit that changes
  a crate and the records describing it takes the crate's scope.
- No new crate and no new dependency: `Cargo.toml` and `Cargo.lock` do not
  change.
- `crates/ridl-core/src/interface_lock.rs` compiles without the `fs` feature;
  only its `read` and `write` are `#[cfg(feature = "fs")]`. `just wasm-check`
  pins this.
- A diagnostic code is declared through `diag_codes!`, in ascending order,
  before it is written anywhere as a string literal, or
  `codes_written_as_string_literals_are_all_catalogued` fails. A code written in
  Markdown is not checked by any test, so every §16.4 row this plan adds is
  checked by reading.
- `classify`, `explain` and `category_word` each carry
  `#[deny(clippy::wildcard_enum_match_arm)]`, and so does the new `heading`. A
  new `Category` variant needs an arm in all four and a rule row in its
  `explain` text, or `every_category_has_a_rule_row_naming_its_verdicts` fails.
- Accept only the snapshots a task names (`cargo insta accept` after reading
  each diff with `cargo insta review` or the `.snap.new` file).
- Each test file in `crates/ridl/tests/` carries its own `TempDir` and `ridl()`
  helpers; there is no shared harness module. A new test file copies them from
  `crates/ridl/tests/baseline_gate.rs`.
- prim does not format or lint a `.lock` file, so a fixture lock file needs no
  `.primignore` entry. A lock file shown in the book is a `text` fence, which
  the examples harness does not compile.
- Never push to `main`, push a tag, or publish. Prose — comments, commit
  messages, documentation — is plain and literal, with no idioms. Never name a
  private or consumer project.

## Plan decisions

The design leaves these choices to the implementation, or its text needed
reading against the code as it is on main. Each decision is the driver's, taken
in stage L2; none changes D-7 or the design's four recorded departures.

- **PD-1 — `ridl diff` given an interface with no identity on the old side.**
  Two source trees compiled with no lock file lower every interface as
  provisional, a case the design's §7 table does not list. The walk runs in
  three passes. (1) An old interface with a frozen, non-zero number matches the
  new interface with the same frozen number. (2) An old interface with no
  identity — `number` 0 or `provisional` — matches by name among the new
  interfaces pass 1 left unmatched. This generalises the §7 row for `number` 0.
  (3) The remaining old interfaces are `InterfaceRetired` when their frozen
  number is in the new side's retired list and `DeclRemoved` otherwise; the
  remaining new interfaces are `DeclAdded`. A frozen old number therefore never
  matches a new provisional interface, so §7 row 4 ("never matched") stands.
- **PD-2 — `RetiredInterface.name`** holds the lock key as written: `LaneAssist`
  for an interface, `service:veh.hvac.cabin` for an inline shape.
- **PD-3 — spans.** RIDL-409 points at the entry's line in `interfaces.lock`.
  RIDL-410 points at the first offending line, or at `0..0` of the file when the
  file is empty or has no `next` line.
- **PD-4 — the package in a message.** `<pkg>` in RIDL-409's text is the package
  directory as the loader recorded it: the parent directory of the lock file's
  path.
- **PD-5 — the rename hint.** `ridl check` does not emit a second diagnostic. It
  adds a secondary `Label` to the RIDL-409 diagnostic, at the span of the one
  same-shape candidate declaration, with the message
  `` same shape as `Old` in the published baseline: run `ridl lock <pkg> --rename Old=New` ``.
  `Diagnostic` has `labels` and `fixits` and no note field
  (`crates/ridl-core/src/diag.rs`).
- **PD-6 — `ridl lock` over a workspace** compiles every package first. Any
  error, other than RIDL-409 under `--rename` or `--retire`, exits 1 and writes
  no package's file.
- **PD-7 — line rules.** The parser skips an empty line and every line whose
  first non-blank byte is `#`, and trims trailing whitespace. A git conflict
  marker line (`<<<<<<<`, `=======`, `>>>>>>>`, `|||||||`) is a line that does
  not parse. The writer and the merge driver always emit the header, `next N`,
  the entries in number order, one `\n` after each line.
- **PD-8 — single-file mode.** A bare `.ridl` file with no manifest reads
  `interfaces.lock` from the file's directory. `ridl-mcp`'s `check_source`
  compiles a string with no directory and reads no lock; every number it lowers
  is provisional.
- **PD-9 — a baseline published before the lock.** RIDL-412 fires only for a
  published interface whose `number` is non-zero. An interface published before
  the lock existed never had an entry, and D-7's "a removed interface that has
  no retired entry" is read as not covering it.
- **PD-10 — ridl §17.14.** #330 added a §17.14 to the ridl reference ("a whole
  interface or service removed … is not refused"), which the design does not
  mention. Its interface half becomes false with RIDL-409 and RIDL-412, so the
  task that adds RIDL-411 and RIDL-412 corrects it and the RIDL-408 row's
  parenthesis. §17.12 and §17.13 stay with stage L5.
- **PD-11 — retired codes stay unused.** `diag.rs` gains
  `pub const RETIRED_RIDL_CODES: &[u16] = &[146, 147, 148];` and a guard test.
  The numbers are integers because a `"RIDL-146"` literal in a `.rs` file fails
  the string-literal guard once the code leaves the catalogue.
- **PD-12 — the lock file in the checker's source map.** `check_package`'s
  source map is indexed by position in `pkg.files`. The lock file takes index
  `files.len()`, and every remapper — `ridlc::load_and_check`, the language
  server's recompute in `crates/ridl-lsp/src/server.rs`, and the corpus
  harness's `compile_entry` in `crates/ridlc/tests/corpus.rs` — pushes the lock
  file's render id last. The language server publishes RIDL-409 under the lock
  file's URI.
- **PD-13 — workspace output.** Over more than one package, each `ridl lock`
  output line is prefixed with the package directory relative to `PATH` and a
  colon: `veh/hvac: allocated CabinClimate 4`. Over one package there is no
  prefix.
- **PD-14 — the path of a renamed interface's changes.** A matched pair uses the
  new side's name in `Change.path`, so the desk check's `DeclIndex` finds a
  span; `InterfaceRenamed` carries `before: Some(old name)` and
  `after: Some(new name)`.
- **PD-15 — sites the design's §9 list omits.** The retirement also changes
  `crates/ridl-backend-proto/src/tests.rs` and
  `crates/ridl-backend-flatbuffers/src/tests.rs` (IR literals with
  `ServiceShape.id`), `crates/ridl-lsp/src/hover.rs` (renders a reserved slot),
  `crates/ridl-core/src/package.rs` (a `ServiceShape::Reserved` arm and a
  fixture string), `crates/ridl-ir/src/lib.rs` (`shapes()`,
  `referenced_packages` and two tests) and `crates/ridlc/tests/corpus.rs` (a
  rendered reserved slot).
- **PD-16 — a fetched package's lock.** No code constructs
  `PackageOrigin::Remote` on main (`git grep` finds none): a fetched package is
  stored in the cache and not yet loaded as a package. The design's §2 promise
  needs no task now. The lock is read in `Loader::load_package_tree`, which a
  remote loader reuses when it is written.
- **PD-17 — not implemented.** The language server's rename code action (design
  §4, "an implementation choice") and a `ridl lock --check` mode (design §5,
  rejected).
- **PD-18 — tracker steps are the driver's.** The census comment on #326 and the
  "G4 holds" comment on #328 are posted by the L4 driver after the merge. They
  are not tasks.

- **PD-19 — the `next` line is found by position.** The first line the parser
  does not skip (PD-7) must be `next N`; every later line is an entry. An
  interface may be named `next` (the word is not a keyword), and its entry is
  the line `next 3` after the header. A second `next N` line is therefore an
  entry, and the malformed shapes of design §2 still catch a hand-edited file.
