## 2. Rulings

- **R-W-23. Item 13: done, no change; tick it.** — `PayloadInfo.max_size` no
  longer exists, so the two numbers cannot disagree; #801's A5 is what settled
  it. — Cost if wrong: none to the code; a wrong tick is undone in the issue.
- **R-W-24. Item 14 and #802: settled by the typl reference §4.3 and #654; no
  `ridl-rt` change; one regression test pins the issue's own example on both
  float wire widths; #802 is closed by this pull request.** — The tolerance is a
  property of the generated check, not of the `ridl-rt` API: `Rule::Step` is
  already a variant, and the check is emitted code. The rule is stated for every
  payload validator, so a proto3 Rust codec (not built yet; the Rust backend's
  only codec is FlatBuffers) inherits it through the same
  `constraint_checks_with_precision` path. The issue's example had no test, and
  no test covered a float64 wire. — Cost if wrong: if a proto3 codec emits its
  own check outside that path, the rule must be applied there; the typl
  reference already requires it, so the gap would be a codec bug, not an open
  question.
- **R-W-25. `Watermark::seq` (item 6's residual): remove the field before
  0.10.0. Breaking; the commit and the pull request title carry `!`.** — `scan`
  never reads it; the one runtime fills it with a maximum taken across
  per-channel counters, which is not a cursor for anything; every `Changed`
  entry already carries its own signal's `seq`. Defining a meaning now would
  freeze an obligation on every runtime for a field no consumer uses. 0.10.0 is
  already a breaking release (#887), so the break costs one more line in the
  changelog. Generated code does not name `Watermark`; the consumers are
  `ridl-loopback`, `ridl-rt-conformance` and hand-written runtimes. — Cost if
  wrong: if a consumer needs a per-interface sequence cursor, adding a field
  back after the freeze is a breaking change; the alternative then is a new
  method or a new type, which is additive.
- **R-W-26. Items 15, 16 and 17: decided and built; no change.** — Evidence in
  section 1. Nothing to tick: the body already ticks them. — Cost if wrong:
  none.
- **R-W-27. Records.** ADR-0021 gains a dated 2026-10-12 amendment in its
  Status, a dated note in place in decision 10 (the sentence that lists the open
  questions) and in Open question 2 (closed), and rows in "Documents amended".
  The design records of `ridl-rt` and `ridl-loopback` follow R-W-25 in the same
  commit as the code. The typl reference is not edited: §4.3 already states the
  rule. — Cost if wrong: a record that disagrees with the code, caught by the
  final review.
- **R-W-28. One pull request.** There is one breaking change (R-W-25); the test
  of R-W-24 and the records do not depend on it but are small, so they travel in
  the same pull request, whose title carries `!`. The plan file moves to
  `docs/archive/` in the last commit, because its content is carried by
  ADR-0021. — Cost if wrong: #802's closure rides on a breaking pull request; if
  that pull request is held, #802 stays open longer.

### Task 1: pin #802's example on a float32 and a float64 wire

Files: `crates/ridl-backend-rust/tests/fixtures/payload_constraints.ridl`,
`crates/ridl-backend-rust/tests/payload_constraints.rs`.

1. Add two named types to the fixture, after `type Fine`:

   ```text
   type Grid32 : float [0.0..100.0 step 0.1]
   type Grid64 : float [0.0..1000000000.0 step 0.1]
   ```

   `Grid32` has 1001 grid values and representable bounds, so its wire form is
   float32; `Grid64` has more than 2^24, so its wire form is float64 (typl
   reference §4.3, the width table).

2. Add one test, `on_grid_decimals_pass_the_step_check_on_both_float_widths`,
   that runs a program through `rustc::run_program` with `program(...)`, in the
   style of `verified_decimal_wire_values_satisfy_the_named_scalar_check`, and
   for each of `Grid32` and `Grid64`:
   - `new(25.3)` is `Ok`, and `new(25.35)` is `Err` with `rule == Rule::Step`;
   - `25.3` encodes, `Ref::verify` accepts the bytes, and the decoded value
     passes `check`;
   - the field's wire width is 4 bytes for `Grid32` and 8 bytes for `Grid64`
     (read it as the existing test does, with `ridl_rt::flatbuffers::root` and
     `ridl_rt::flatbuffers::field`);
   - overwriting the field with `25.35` at that width makes `verify` return
     `VerifyError::Contract` with `rule == Rule::Step`.

3. Show the test pins the tolerance: in
   `crates/ridl-backend-rust/src/scalar_step.rs`, temporarily replace the
   `__tolerance` expression with `0.0`, run the new test, record in the report
   that it fails, then restore the file exactly (`git diff` empty for that
   file). Mutate in place; the target directory is shared.

4. Check that no other test reads the fixture's declaration count or a snapshot
   of it; if one does, update it.
