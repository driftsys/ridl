## Why this lane exists

On 2026-09-20, after lane R merged, `ridl build --emit rust` writes a crate that
holds a package's domain types and nothing else. Five layers sit between that
crate and a contract an application can run:

| Layer                 | Today                                                                                  | Missing                                  |
| --------------------- | -------------------------------------------------------------------------------------- | ---------------------------------------- |
| The domain types      | value objects for constrained scalars, enums and patterns; the crate compiles          | lane C's Tasks 4, 6 and 11 (Epic 10)     |
| The face              | `generate_face` works, and only the backend's own test tree calls it                   | a story wiring it into `ridl build`      |
| The payload codec     | none; `tests/interaction_face.rs` hand-writes `Payload<ReprC>` for the fixture's types | E11.7, E11.8, E11.12                     |
| A runtime             | `tests/support/loopback.rs`, a test double its own documentation says to read out      | the `ridl-loopback` crate of ADR-0020 d6 |
| The frame and catalog | no frame specification; the face checks a zero catalog hash                            | E11.1, Epic 16                           |

The generated face is generic over its port and calls `Payload<E>` on every
domain type it carries, so the face cannot be built outside the fixture where
those impls are hand-written. Nothing outside this repository can generate a
face at all, because `ridl build` reaches `generate` and not `generate_face`
(ADR-0023 decision 2 and its last consequence). And nothing gives `Client::new`
an argument, because the engine is outside this repository, as the roadmap's
Epic 11 section records, and the loopback runtime has not been built.

**The lane's exit criterion.** A package built by `ridl build --emit rust`, the
command and not the library entry point, produces a crate that links `ridl-rt`
and `ridl-loopback`, and a signal, an event, a command and a query round-trip in
one process through generated `Payload<FlatBuffers>` impls, with nothing
hand-written but the provider. That is the in-process demonstration. The
cross-process one adds E11.1, the WebSocket half of E11.9 and Epic 16's catalog
hash, and is the next lane, not this one.

**What this lane does not do.** E11.8 and E11.12, the second and third codecs.
E11.1 and the WebSocket transport. Epic 16. The TypeScript face. Any change to
the port traits: no `Send` or `Sync` bound, no new method.

### K1 — the codec design note, then its plan. Branch `docs/flatbuffers-codec-design`.

A design note in `docs/wip/`, named `<date>-flatbuffers-codec-design.md`, of the
shape of `docs/archive/2026-09-16-interaction-face-v0-design.md`: scope, the
shape of what is emitted, the decisions with their alternatives, what does not
change, the open items, the records to amend. Then, once Sebastien has disposed
of its decisions, the implementation plan beside it,
`<date>-flatbuffers-codec-plan.md`, of the shape of
`typl-value-objects-plan.md`: one task per pull request, test first, the model
named per task, the exact files.

**Why FlatBuffers first.** The encoding matrix of ADR-0020 decision 2 gives
FlatBuffers to everything mapped or passed within a node and to the wasm codec
boundary, which is the in-process runtime of K4 and step 2's TypeScript face.
ADR-0019 already fixes the projection, so the layout is decided and only the
codec is open. `ridl-rt`'s `Malformed` variants (`OutOfBounds`, `Unaligned`,
`MissingRequired`, `Utf8`, `Union`, `TooDeep`, `TooManyTables`, `TooLarge`) are
a FlatBuffers verifier's failure set, and ADR-0021 decision 8 already settles
that the `flatbuffers` dependency, and the global-allocator obligation it brings
under the feature, arrive with E11.7 as an additive change.

**The note must answer these, each as a numbered decision with the alternative
it rejects.** They are the questions a reviewer will ask; a note that leaves one
open leaves the plan unwritable.

1. **The impl per type kind**, under ADR-0019's projection: a named scalar, a
   struct (every struct is a `table`), an enum, an enum set, a union in its
   wrapper table with a non-table arm boxed, a list, a map with no `(key)`, an
   optional, a string with its bounds, and the `= null` default on a field whose
   enum declares no zero member.
2. **The `View`.** ADR-0021 decision 7 expects an accessor over the bytes, read
   in place, and permits `unsafe` inside a `flatc`-style accessor while
   forbidding it in code ridl emits. Decide whether the accessor is generated by
   this backend over the `flatbuffers` crate's `Table` and `Follow` primitives,
   which ADR-0020 decision 5 permits under the feature, or is hand-rolled in
   `ridl-rt` with no dependency. The issue for E11.7, driftsys/ridl#263, says
   the codec is generated and not delegated, for the reason the projection is
   ours (ADR-0018 decision 4); state what that rules out.
3. **`verify` in one pass.** Structure, which is the FlatBuffers verifier's
   rules mapped onto `Malformed`, and the typl constraints of every value the
   buffer holds, mapped onto `Violation`, in one pass over the bytes, as the
   `Payload` trait's documentation requires.
4. **`encode` into a caller's slice.** `Payload::encode` writes into `&mut [u8]`
   and reports `EncodeError::Capacity`. A FlatBuffers builder writes back to
   front and the crate's builder owns a `Vec`. Decide whether the generated
   encoder builds in the caller's slice with no allocation, or builds in the
   crate's builder and copies, and state what each costs on `wasm32` and under
   `no_std`. ADR-0021 decision 8 has accepted the allocator obligation under the
   feature; that is not a reason to spend it.
5. **`decode` across the validating seam.** After `verify`, a value is known to
   satisfy its constraints, and Epic 10's rule is that no path constructs a
   value except the validating one (the value-objects design, decision 7, and
   Task 6). Decide how a verified view becomes a domain value without checking
   twice and without a public unchecked constructor: the codec impl and the
   type's private field are emitted into the same module, so a constructor
   visible only there is available. Whatever is chosen must hold after lane C's
   Task 6 lands, so read that task's landed shape before deciding.
6. **`MAX_SIZE`.** The bound per type, and what a type with no finite bound
   does. Epic 16's E16.3 and E16.4 compute the same bounds for the catalog
   descriptor; decide where the one computation lives so the codec's constant
   and the descriptor's number cannot disagree. The `PayloadInfo.max_size`
   fields the face emits are `None` today for that reason.
7. **Where the impls are emitted.** `generate` may now name `ridl_rt`: the
   corpus rustc proofs in `crates/ridlc/tests/corpus.rs` pass the `ridl_rt` rlib
   to rustc since Epic 10 Task 3, which removes the constraint ADR-0023 decision
   2 records. Decide whether the impls go beside the types in `generate`, always
   or when the package selects the encoding, and how the generated `Cargo.toml`
   of Epic 10 Task 7 declares the feature.
8. **The face's encoding.** The generated face computes its dispatch bound over
   `<T as Payload<ReprC>>::MAX_SIZE`, a placeholder from E11.13. Decide whether
   the face becomes generic over the encoding or the encoding is selected per
   package, and how the fixture's hand-written `Payload<ReprC>` impls in
   `crates/ridl-backend-rust/tests/interaction_face.rs` are replaced by
   generated `Payload<FlatBuffers>` ones.
9. **Conformance.** E11.8 is specified with byte-level conformance against a
   `protoc`-generated implementation. State the equivalent here: our bytes read
   by `flatc`-generated Rust or by the `flatbuffers` crate over the emitted
   `.fbs`, and theirs by ours, in a test with a dev-dependency only.
10. **driftsys/ridl#302.** A union-arm retirement shifts FlatBuffers wire
    discriminants silently. The roadmap lists it as a defect to clear with this
    work; say what the codec does about it, or why it is the projection's and
    not the codec's.
11. **driftsys/ridl#350.** The thirteen `ridl-rt` API questions name the codecs
    as evidence for several items, among them the stack buffers sized from
    `MAX_SIZE`. Dispose of every item this note can, on the issue, and leave the
    rest named.
12. **The `ridl-rt` change.** What the `flatbuffers` feature comes to hold, the
    dependency's version, and the proof that `just wasm-check` and
    `just compat-check` (edition 2021 at the crate's `rust-version`, and edition
    2024 at the pin) still pass with the feature on and off. The change is
    additive; do not bump the crate version.

Also settle here, as its own section, the two questions K3 executes, because
they change what the note's decision 7 emits: how `ridl build` selects the face
emit (a `--emit` value or a `ridl.toml` key, under ADR-0010's conventions), and
what happens to a corpus entry whose contract clause the translator of ADR-0023
decision 1 refuses. The default `ridl build` must not start failing on a package
that built yesterday, so until E5.1 lands the face is opt-in, or the refusal is
scoped to the interface, or something better the note argues for.

**Gate for the plan.** Sebastien's disposition of every decision, as a comment
on the design note's pull request, as driftsys/ridl#429 carried for lane R. Do
not write the plan before it. A decision he amends is rewritten in the note
before the plan cites it.

Commits: `docs(docs)`.

### K4 — E11.15, `ridl-loopback`. Branch `feat/ridl-loopback`.

A new crate at `crates/ridl-loopback/`, depending on `ridl-rt` and nothing else
(ADR-0020 decision 6). Read the backend's test double, `loopback.rs` under
`tests/support/`, out into it, as that file's own documentation asks, and give
it the handle model of ADR-0021 decision 12:

- one handle type per port role, that is per port trait, for every trait the
  crate implements; whether it implements `ScannableSignals` and
  `CoherentSignals` is a decision the pull request states;
- an aggregate handle covering the port set one interface's face needs, which is
  what `Client::new` and `Publisher::new` are handed when the bound is
  multi-trait;
- the `Send`/`Sync` split as the rule states it: a handle whose port traits all
  take `&self` is `Send + Sync`, a handle carrying a `&mut self` method is
  `Send`, an aggregate is `Sync` only if every handle it holds is. The compiler
  derives it; pin it with a test that names each handle's bounds;
- a clock the test advances by hand, as the double has, and no IO.

The backend's round-trip tests move onto the crate and the test double is
deleted. A new crate adds its scope to `.git-std.toml`, its row to the workspace
`Cargo.toml`, and its name to the crate list in `AGENTS.md` and to
`docs/technotes/walking-skeleton-architecture.md`. `just wasm-check`'s crate
list is a decision: the loopback holds every value in memory and needs `std`
collections, so say whether it joins that list or why not.

**Then the exit test**, in the crate's `tests/`: an example package, built by
running the `ridl` binary with `--emit rust` on a fixture package (the way
`crates/ridlc/tests/corpus.rs` drives rustc, not the library API), compiled, and
a provider and a consumer exchanging a signal, an event, a command and a query
over the loopback's aggregate handle. That test is the lane's exit criterion,
and it is what the next lane's transport test copies.

Commits: `feat(ridl-loopback)`, after the scope exists.

## What does not change

- ADR-0021 decision 7: the encoding set is closed, `Ref` is the only proof, and
  `decode` is reachable only through it. No `unsafe` in code ridl emits.
- ADR-0021 decision 12 and ADR-0023 decisions 3 to 5, as lane R landed them: a
  face holds its port by value, its correlations are typed, a `Provider` method
  takes its argument by reference, and no port trait carries `Send` or `Sync`.
- ADR-0020 decision 3: a generated domain struct carries no `#[repr(C)]`. That
  is E11.12's, not this lane's.
- The port traits' methods and receivers. A codec is reached through
  `payload::Ref` and never through a port.
- Epic 10's derive set and validating seam. Decision 5 of the note works with
  them, not around them.

## Mechanics

Worktree `.claude/worktrees/lane-k-codegen`, created in K0 as a git worktree and
bootstrapped with `./bootstrap`. Branch fresh from `origin/main` for every
stage.

`git branch --show-current` before every commit and every push. **Stage explicit
paths, never `git add -A`.** Test first for K2, K3 and K4: write the failing
test, run it, then the change. `cargo fmt --all` before every Rust commit,
`just fmt` before every Markdown commit. Read every diff yourself before it goes
near a pull request.

Gate before a pull request: `just verify`. Review as above, ledger on the pull
request, pass 2 if pass 1 kept findings, `just verify` again, squash-merge,
update local `main`. One pull request open at a time.

Close a story issue when its stage merges; closing never rewrites a body.

### Facts about a cloud session

- The repository's `.claude/hooks/session-start.sh` installs just, prim, mdbook
  and git-std at the start of a session on Claude Code on the web. If git-std is
  still missing, its release installer answered 403 through the proxy; install
  it from source with cargo, the way `ci.yml` does:

      cargo install --git https://github.com/driftsys/git-std git-std --locked

- The container runs as root, and two tests assert on permission bits that do
  not apply to uid 0: driftsys/ridl#430 and driftsys/ridl#434. If those are the

  the pull request, and run `just lint`, `just wasm-check`, `just compat-check`
  and `just check` yourself, because `just build` stops at `test`. CI's runner
  is not root.
